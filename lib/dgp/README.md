# DGP（欲望大奖赛）详细 README

> 这份文档基于当前项目中 `components/dgp/DgpGame.tsx`、`lib/dgp/engine.ts`、`lib/dgp/data.ts`、`lib/dgp/constants.ts`、`lib/dgp/logic.ts`、`lib/dgp/types.ts` 的**实际实现**整理。
>
> 它描述的是“代码真实行为”，而不只是界面文案。

---

## 1. 这是什么游戏

DGP 在 UliUli 里不是一个手动操作型小游戏，而是一个：

- **自动演算**的生存战斗模拟器
- **以骑士代号建档**的伪角色生成器
- **带随机事件、装备演化、场地异变、怪物乱入、悬赏与隐藏奖励**的观战型系统
- **支持 Seed 复现**的可回放对局系统

你在一局 DGP 中真正会做的事情只有三件：

1. 输入至少 2 个骑士代号
2. 可选填写一个 `SIMULATION_SEED`
3. 开始对局，然后暂停 / 继续 / 单步观看

对局中的角色行为、出招、抢资源、互殴、杀怪、掉落、爆种、场地变化，全部由引擎自动决定。

## 2. 代码结构

## 2.1 用户入口

- **大厅入口**：`components/GameModal.tsx`
- **DGP UI 主组件**：`components/dgp/DgpGame.tsx`

## 2.2 规则与数据

- **主引擎**：`lib/dgp/engine.ts`
- **带扣 / ID Core / 邪魔徒 / 支持者 / 场地 / 隐藏任务**：`lib/dgp/data.ts`
- **平衡性常量**：`lib/dgp/constants.ts`
- **带扣评分 / 目标威胁 / Buff 应用**：`lib/dgp/logic.ts`
- **随机数与可复现种子**：`lib/dgp/rng.ts`
- **类型定义**：`lib/dgp/types.ts`
- **工具函数（深拷贝 / hash / XSS 转义）**：`lib/dgp/core.ts`

## 2.3 架构特点

- **UI 与规则彻底分离**：UI 只负责输入、播放日志、展示快照
- **日志驱动回放**：每条日志都可附带 `snapshot`，HUD 会跟着日志同步更新
- **所有关键随机都挂到同一个 RNG 上**：同一阵容 + 同一 seed = 同一对局流程
- **战斗并非逐帧实时渲染**：而是“每回合算出日志队列 -> 按 delay 播放”

## 3. 用户视角的玩法流程

## 3.1 开局准备

在 `DgpGame` 的 `setup` 阶段：

- 输入骑士代号
- 每个代号会自动生成一名骑士
- 至少需要 **2 人** 才能开始
- 可选填写 `SIMULATION_SEED`

限制：

- **空名字无效**
- **重复名字不能添加**

## 3.2 战斗播放

开始后界面会自动进入 `battle` 阶段：

- 左侧是幸存者 / 邪魔徒 HUD
- 右侧是直播日志流
- 顶部会闪现当前场地异变
- 正在行动者和被命中的目标会高亮

你可以使用的控制：

- **`PAUSE_STREAM`**：暂停自动播放
- **`RESUME_STREAM`**：继续自动播放
- **`NEXT_CYCLE`**：手动推进下一回合
- **`INITIALIZE_NEW_DGP`**：回到建档界面重新开局

## 3.3 胜负结束

当满足胜负条件后，引擎会在日志里推送 `isGameOver`：

- 如果有人夺冠，显示 `NEW WORLD CREATED`
- 如果全员死亡或人类全灭，则无冠军

## 4. 开局生成机制

每个骑士代号不是纯装饰，而是**直接参与数值生成**。

`DgpGame.tsx` 的生成逻辑如下：

```ts
const nameHash = generateHash(name)

str = 20 + (nameHash % 81)
agi = 20 + ((nameHash >> 3) % 81)
int = 20 + ((nameHash >> 5) % 81)

baseHp = 4800 + str * 64
baseAtk = 25 + floor(str * 1.5 + agi * 0.5)

idCore = ID_CORES[nameHash % ID_CORES.length]
```

这意味着：

- **名字决定力量 / 敏捷 / 智力**
- **名字决定基础 HP / ATK**
- **名字决定分配到哪一个 ID Core**
- 同一个名字每次都会生成同样的初始骑士

### 4.1 初始状态

所有人开局默认：

- `buckles = []`
- `inventory = null`
- `feverSlot = null`
- `shield = 0`
- `buffs = []`
- `kills = 0`
- `status = alive`

也就是说，所有骑士开局都是**素体形态**。

## 5. 胜负条件

引擎的最终判定非常明确：

## 5.1 人类获胜

当且仅当：

- 场上只剩 **1 名存活的人类骑士**
- 并且 **没有存活邪魔徒**

此时该骑士成为欲望神。

## 5.2 人类尚未获胜

如果：

- 只剩 1 名人类
- 但场上还有邪魔徒

那么比赛**不会立刻结束**，而是进入“孤军奋战”状态，这名骑士必须把剩下的邪魔徒全部杀光。

## 5.3 失败 / 无人胜利

以下情况都算没有冠军：

- **所有人类全灭，邪魔徒仍然存活**
- **人类和邪魔徒同归于尽**

## 5.4 分身不算冠军

`clone` 只是临时召唤物：

- 不算真正参赛骑士
- 不计入最终获胜人数
- 不会单独成为胜者

## 6. 核心实体与资源系统

## 6.1 实体类型

| 实体 | 来源 | 是否计入最终胜负 | 特点 |
| --- | --- | --- | --- |
| 人类骑士 | 用户输入名字生成 | 是 | 有 ID Core、可装备带扣、可拿悬赏、可触发隐藏任务 |
| 邪魔徒 | 环境生成 / 贝洛芭进化 | 否 | 会打人、会乱入、后期能变成 Boss |
| 分身 | 忍者技能召唤 | 否 | 临时协战单位，时间到自动消失 |

## 6.2 骑士的装备位

| 槽位 | 字段 | 作用 |
| --- | --- | --- |
| 主驱动器左 / 右槽 | `buckles[0]` / `buckles[1]` | 核心武装来源 |
| 备用槽 | `inventory` | 满装备时的后备带扣 |
| 狂热外置槽 | `feverSlot` | 狂热轮盘产物，不占正常双槽 |
| 护盾值 | `shield` | 吸收伤害，并抵抗部分负面状态 |
| Buff 列表 | `buffs` | 中毒、灼烧、锁定、破甲、幻影等 |

## 6.3 带扣地面掉落

引擎有一个 `groundBuckles`：

- 记录战场上遗落的高级带扣
- 角色可以优先从地上捡
- 如果地面物资太多，场务会清理旧掉落

**实际代码规则**：当地上物资数大于 3 时，会只保留较新的 2 个。

## 7. 完整回合流程

每一回合 `calculateNextRound()` 的顺序是：

1. **`handleEvents()`**
   - 处理场地异变
   - 悬赏
   - 支持者空投
   - GM 狂热
   - 指挥带扣空投
   - 隐藏任务
   - 邪魔徒刷怪

2. **`handleCombat()`**
   - 按先手顺序依次让存活单位行动
   - 先做回合前处理
   - 再决定拾取还是攻击
   - 再结算死亡与击杀

3. **`handleEnvironment()`**
   - 场地 DOT / 治疗
   - 中毒 / 灼烧 / Regen 结算
   - Buff 回合数递减
   - 分身持续时间减少

4. **清除待移除单位**

5. **检查胜负**

6. **回合数 +1**

### 7.1 行动顺序

所有存活单位会按以下顺序排序：

```ts
有效敏捷 + 0~50 随机值
```

额外规则：

- 有 `Burst` 的单位，先手值额外 `+1000`
- `Wet` 会让有效敏捷变成原来的 `70%`

所以 DGP 并不是严格拼面板，而是：

- **敏捷主导**
- **爆发状态绝对抢先**
- **有小幅随机扰动**

## 8. 战斗前处理

角色在正式行动前，会先进入 `_processPreActions()`。

## 8.1 眩晕挣脱

如果角色处于 `Stun`：

- 挣脱概率 = `(str / 100) * 0.3`
- 成功则本回合继续行动
- 失败则本回合直接跳过

也就是说，力量越高，越容易强行顶掉眩晕。

## 8.2 大带扣交易

当人类骑士满足以下条件时，可能触发自动交易：

- 自己活着
- 不是邪魔徒 / 不是分身
- 没有 `Command_Twin`
- 自己身上至少有一个 `large / legendary / mythic` 带扣
- 遇到另一个也有高级带扣的人类
- 交换后对双方评分都更高
- 再通过一次 `60%` 的交易接受判定

### 与推进器相关的特殊交易规则

如果交易涉及 `Boost`：

- **Fox 持有者**：不会被骗交出去
- **Tanuki 持有者**：有 `60%` 概率被骗交出推进器
- **其他人**：有 `15%` 概率被骗交出推进器

## 8.3 狂热轮盘（Fever Roulette）

只要角色：

- 是人类
- 不是分身
- 没有 `Command_Twin`
- 装备了 `Fever`

就会每隔一段时间启动狂热轮盘。

### 轮盘冷却

- 每次摇奖后冷却 `3` 回合
- 如果当前还没有 `feverSlot`，也会立即补摇

### 轮盘档位

| 档位 | 触发条件 | 结果 |
| --- | --- | --- |
| `SSS` | `r > 15` 后可出现；普通人 `5%`，Tanuki `10%` | 抽到 `Boost`，并进入大奖爆发准备态 |
| `C` | 普通人 `20%`，Tanuki `0%` | 抽到一件真实的小型带扣并装备到 `feverSlot`，额外获得 `50` 点安慰护盾 |
| `S` | 固定中档 | 只会复制**当前双槽里**另一件可复制的大带扣，进入大奖爆发准备态 |
| `A` | 其余情况 | 从五大基础大带扣里抽一个；默认避开 `S` 档复制源，也不会和备用槽 `inventory` 同名 |

### 轮盘的重要结论

- `Tanuki` 是最稳定的 Fever 使用者
- `SSS` 早期被锁到 **15 回合之后**
- 轮盘产物放在 `feverSlot`，不占双槽
- `C` 档位现在也会注入真实的小型带扣技能与属性，而不再只是搞笑占位物
- `S` 档位**不看备用槽 `inventory`**，并且会跳过 `Command_Raising` 与 `Command_Twin`
- 当 `jackpotBurstReady = true` 时，下一次攻击会优先打出大奖技能

## 9. 拾取与装备机制

## 9.1 行动类型：抢物资还是开打

人类骑士每回合会先决定：

- **`loot`**：捡地上的 / 开补给箱
- **`attack`**：直接战斗

AI 倾向：

- 0 个带扣时，`80%` 概率去捡
- 1 个带扣时，`60%` 概率去捡
- 装备很差 / 备用槽空时，也更倾向搜物资
- 地上有好东西时，也会被吸引

## 9.2 带扣评分

AI 判断一个带扣值不值得拿，核心依赖 `calculateBuckleScore()`。

高优先级顺序大致是：

1. `Command_Raising` / `Command_Twin`
2. `Fever`
3. `Boost`
4. 自己的 `ID Core affinity`
5. 其他大带扣 / 小带扣，按属性偏好加权

## 9.3 地上捡物规则

角色会优先评估地上的带扣是否**严格强于自己当前最差的装备**：

- 如果更强，就会去捡
- 如果只是垃圾，通常不会浪费回合
- 若地上是自己已有的同名带扣，而且自己血没满，会把它当成“回血包”优先捡起

## 9.4 补给箱抽卡规则

如果地上没值得拿的东西，就会去开未知补给箱。

补给箱的可出物：

- 排除 `Entry`
- 排除 `Fever`
- `Boost` 在 **15 回合前不会进普通箱池**
- 排除自己已拥有的带扣
- 排除 `Command_Raising`
- 排除 `Command_Twin`

也就是说：

- `Fever` 不是常规野生掉落
- `Command` 系列不是常规野生掉落
- `Boost` 属于中后期资源

## 9.5 物资争夺战

当一个人准备拿到带扣时，有 `20%` 概率和另一个空闲人类发生争夺：

- 比拼值 = `ATK + 有效 AGI + 0~100 随机`
- 胜者对败者造成一次即时伤害
- 胜者拿走带扣
- 如果这一下打死人，还会照常结算悬赏奖励

## 9.6 装备时会发生什么

`equipBuckle()` 是 DGP 里最重要的函数之一。

### 规则 A：双重指挥排他

如果角色已经持有 `Command_Twin`：

- 不能再装备任何新带扣

### 规则 B：拿到重复带扣 = 回血

如果你已经有同名带扣：

- 不会再叠一份
- 而是回复 `该带扣 hp 加成的一半`
- 若中毒，治疗减半

### 规则 C：满槽后会进行优胜劣汰

如果双槽已满：

- 会把当前 2 件装备 + 新带扣一起评分
- 最差的会被替换、放进备用槽或丢到地上

### 规则 D：高级带扣可能掉到地上

`large / legendary / mythic` 被淘汰时：

- 会掉落到战场地面
- 其他人之后可以去捡

### 规则 E：触发形态播报

当形成双槽组合时，会出现：

- **`ARMED`**：普通双槽组合
- **`DUAL ON`**：双高级武装 / 狂热双持等强组合
- **`REVOLVE ON`**：槽位替换后的重组进化

## 10. 攻击与目标选择

## 10.1 技能来源

### 人类骑士

正常情况下：

- 如果没有带扣：使用 `Entry` 素体技能
- 如果只有 1 个带扣：这个带扣提供全部可用技能
- 如果有 2 个带扣：
  - `slot0` 提供 `attack / ultimate`
  - `slot1` 提供 `tactical`
- `feverSlot` 也会额外提供技能

### 邪魔徒 / 分身

- 直接使用自身 `skills`

## 10.2 技能抽取权重

如果不是大奖爆发，技能从候选池里按权重抽：

| 技能类型 | 权重 |
| --- | --- |
| `dual_ultimate` | 5 |
| `ultimate` | 3 |
| `tactical` | 2 |
| `attack` | 1 |

这意味着：

- 只要冷却允许，角色更偏向打强技能
- 双必杀是最容易被挑中的高价值动作

## 10.3 目标优先级

目标排序由 `getThreatScore()` 控制。

### 人类的一般倾向

- 场上有邪魔徒时，**大多数情况优先打邪魔徒**
- 但如果有悬赏目标，且随机倾向命中，会强烈转火
- 若怪全清了，就会开始内斗

### 邪魔徒的一般倾向

- 通常优先攻击人类
- 但在终盘“失控内斗”状态时，有概率互相残杀

### 特别加权

以下目标会更容易被选中：

- 悬赏目标
- 低血单位
- 已被 `Vulnerable` 的单位
- 对特定技能相性差的单位

## 11. 伤害结算公式

DGP 的基础伤害分成两类：

```ts
物理基础伤害 = (atk * 1.0 + str * 1.5) * skill.dmg / hits
魔法基础伤害 = (int * 2 + atk * 0.5) * skill.dmg / hits
```

然后再叠加各种修正：

- 擦伤：`x0.3`
- 攻击提升 `Atk Up`：`x1.3`
- 爆发 `Burst`：`x1.5`
- 目标破甲 `Vulnerable`：`x1.3`
- 条件达成（例如有分身 / 目标被锁定）：按技能 `condMult` 加成
- 属性契合带扣在身上：人类额外 `x1.3`
- `ignoreDef`：伤害乘上 `1 + ignoreDef`
- `trueDmg`：再额外 `x1.5`
- 最终每击还有一次 `0.9 ~ 1.1` 的随机浮动

## 11.1 DGP 保护协议

只要满足：

- 场上有邪魔徒
- 回合数 `< 50`
- 攻击者和目标都是人类

那么会触发人类内斗保护：

- 人打人伤害只剩 **35%**

到了 **第 50 回合**，保护协议会被永久解除。

## 11.2 护盾结算

- 护盾先于 HP 吸收伤害
- 若技能不带 `ignoreShield`，伤害先扣护盾
- 若技能带 `ignoreShield`，会直接贯穿并清空护盾

## 11.3 击飞掉落（Disarm）

如果一次攻击对目标造成的总伤害：

- 超过目标 `maxHp * 0.4`
- 目标仍然活着
- 目标是人类而非怪物 / 分身

就有 `30%` 概率把目标的一件高级带扣打飞。

后续会发生两种情况：

- 普通骑士：`50%` 概率顺手抢走
- `Bull`：`80%` 概率顺手抢走
- 否则掉到地上

## 12. 命中、闪避、暴击与反伤

## 12.1 闪避

基础闪避概率近似为：

```ts
有效敏捷 * 0.0015
```

再叠加：

- `Phantom`：本次必闪一次，然后消耗
- `Dodge Up`：`+20%`
- `Cat / agile`：基础额外闪避，Fever 下更高
- `Midnight`：`+30%` 闪避
- `Wet`：让有效敏捷变成 `70%`

## 12.2 命中修正

以下情况可以强行命中或部分命中：

- 技能自带 `alwaysHit`
- 目标带有 `Locked-on`
- `Eagle / precise` 被动可在很多情况下无视基础闪避
- 被强制命中的闪避会变成“擦伤”，而不是完全 miss

## 12.3 暴击

暴击主要来自：

- `Fox / crit` 被动
- 技能自带 `alwaysCrit`
- `Midnight` 强制暴击
- `Locked-on` 会提升人类的暴击机会
- 持有 `Fever` 时，暴击率和暴伤都更凶

## 12.4 低血爆发

`Wolf / blood`：

- 低血时会获得显著增伤
- 持有 `Fever` 时低血阈值更宽，增伤更夸张

## 12.5 反伤

`Pumpkin / thorns`：

- 受到伤害时会反弹部分伤害给攻击者
- 若目标携带 `Fever`，反伤比例更高

## 13. Buff、Debuff 与护盾规则

## 13.1 状态效果一览

| 状态 | 实际作用 |
| --- | --- |
| `Poison` | 回合末损失 `3% maxHp`；所有治疗减半；毒气沼泽里会吃更重环境伤害 |
| `Burn` | 回合末优先融化护盾；无护盾时造成 `4% maxHp` 伤害 |
| `Stun` | 行动前判定挣脱，否则本回合跳过 |
| `Vulnerable` | 受到的伤害提高 |
| `Locked-on` | 更容易被精准打击与暴击，并强化部分 Magnum 终结技 |
| `Wet` | 有效敏捷降为 `70%`；会让毒沼更疼，也会提高魔法打击威胁 |
| `Phantom` | 保底闪掉一次攻击，然后移除 |
| `Atk Up` | 输出提高 |
| `Regen` | 回合末按已损血量回复 `15%` |
| `Burst` | 输出提高且行动顺序大幅提前 |
| `Dodge Up` | 额外闪避 |

## 13.2 护盾的额外规则

`applyBuff()` 里有一条非常关键的隐藏规则：

只要目标当前 `shield > 0`，就会**抵抗以下负面状态**：

- `Poison`
- `Stun`
- `Vulnerable`
- `Locked-on`
- `Wet`

所以护盾不只是“第二条血条”，还是**异常状态防火墙**。

## 14. 回合结束环境结算

`handleEnvironment()` 会在每回合战斗后统一结算环境与持续效果。

## 14.1 毒气沼泽

- 正常单位：损失 `10% maxHp`
- 若已经 `Poison` 或 `Wet`：损失 `20% maxHp`

## 14.2 停战休整区

- 仅人类骑士享受治疗
- 回复 `10% maxHp`
- 中毒时治疗减半

## 14.3 中毒

- 每回合额外掉 `3% maxHp`
- 会追溯施毒者，若毒死目标，击杀和悬赏奖励会算到施毒者头上

## 14.4 灼烧

- 有护盾时优先融化护盾
- 无护盾时烧 HP

## 14.5 Regen

- 每回合回复 `(maxHp - hp) * 0.15`
- 中毒时治疗减半

## 14.6 分身寿命

- 分身每回合会减持续时间
- 时间归零时自动消失

## 15. 特殊事件系统

## 15.1 场地异变

### 触发规律

- 第 **10 回合**必定首次触发
- 每个场地持续 **3 回合**
- 场地结束后，至少间隔 **5 回合** 才可能再次触发
- 达到冷却间隔后，每次有 **50%** 概率开启新场地

### 场地列表

| 场地 | 类型 | 实际代码效果 |
| --- | --- | --- |
| 停战休整区 `Ceasefire` | safe | 人类在有怪且保护协议仍生效时，人打人伤害变成 0；人类回合末回血 10% |
| 绝对防御阵地 `Defense` | safe | 所有伤害减半；护盾类效果翻倍 |
| 极度深寒 `Zero` | safe | 冷却**不会递减**；`Boost` 技能被禁用。注意：代码并没有把所有非推进器技能一刀切禁掉 |
| 修罗竞技场 `Asura` | danger | 开场清空所有护盾；关闭 DGP 保护协议；后续护盾生成失败 |
| 毒气沼泽 `Toxic` | danger | 回合末对所有存活单位造成环境伤害；中毒 / 湿身者更痛 |
| 暗夜捉迷藏 `Midnight` | danger | 全体闪避大幅提高；一旦命中，强制带暴击修正 |
| 邪魔徒狂欢节 `Carnival` | chaos | 邪魔徒攻击力 `x1.5`，并获得高额吸血；刷怪几乎停不下来 |
| 失重迷宫 `Labyrinth` | chaos | 单体攻击会被改写为随机指向任意其他存活单位 |

## 15.2 悬赏系统

### 触发条件

- 最早从 **第 13 回合**开始尝试
- 本局尚未触发过悬赏
- 当前没有存活悬赏目标
- 通过一次 `15%` 概率判定
- 存活实体（不含分身）至少 3 个

### 目标选择

- 直接把**当前 HP 最高的存活实体**设为悬赏目标

### 持续时间

- 悬赏持续 **3 回合**

### 被击杀的奖励

击杀悬赏目标后：

- 击杀者回复缺失生命值
- 若击杀者中毒，回复量减半
- 若击杀者是人类：
  - 默认奖励 `Fever`
  - `r > 15` 时，有 `50%` 改发 `Boost`

### 活过悬赏的奖励

如果目标撑过 3 回合没死：

- 人类：回满缺失生命，并获得 `Fever`
- 邪魔徒：获得 `Atk Up` `3` 回合

### 重要细节

- **悬赏系统每局最多触发一次**，因为 `bountyTriggered` 一旦为 `true` 不会重置

## 15.3 GM 狂热大奖

触发条件：

- 最早可能在 **第 20 回合**
- 需要场上至少有 **2 个 Boss 邪魔徒**
- 或者无论如何到了 **第 25 回合** 强制触发

效果：

- 所有存活人类统一发奖励
- 没有 `Fever` 的发 `Fever`
- 已有 `Fever` 的改发 `Boost`

这是整个 DGP 中后期节奏的核心拐点。

## 15.4 指挥带扣空投（Command 系）

`Command_Raising` 不会从普通补给箱里出现，它只会通过全局事件投放。

规则：

- 在 GM 狂热触发后 **第 3 回合** 空投第一把 `Command_Raising`
- 在 GM 狂热触发后 **第 8 回合** 空投第二把 `Command_Raising`
- 两次空投都是全场争夺焦点

## 15.5 支持者空投

触发概率：

```ts
0.15 + round * 0.015
```

也就是说回合越后面，赞助商越活跃。

支持者列表：

| 支持者 | 目标带扣 |
| --- | --- |
| 吉恩 `Ziin` | `Magnum` |
| 凯凯拉 `Kekera` | `Ninja` |
| 秋恩 `Kyuun` | `Beat` |
| 贝洛芭 `Beroba` | `Zombie` |

### 投放逻辑

- 会在全体存活人类中，找出对该带扣“评分最高”的人
- 如果该人已经有对应带扣，则可能转成 `Boost` 或其他高级替代奖励

### 贝洛芭的特殊规则

如果抽到 `Beroba`：

- 会优先尝试把一只存活的 `Pawn` 步兵进化成 `Rider`

## 15.6 隐藏任务

### 机制

- 每局开局会从 `SECRET_MISSIONS` 里随机抽出 **1 个隐藏任务**
- 之后每回合按 `0.08 + round * 0.01` 的概率尝试触发
- 只能完成 **一次**

### 可参与人群

引擎会优先找“弱势人类骑士”：

- 活着
- 不是怪物 / 不是分身
- 当前没有 `large / legendary` 武装

### 任务池

| 任务 | 条件 |
| --- | --- |
| 绝境求生 | 当前生命比例 `<= 35%` |
| 素体的觉悟 | 完全没带扣 |
| 和平的守护者 | `kills === 0` |
| 伤痕的勋章 | 已掉血量大于 `600` |
| 风之轨迹 | `agi > 60` |
| 绝对力量 | `str > 60` |
| 战术天才 | `int > 60` |
| 茨姆莉的捉迷藏 | 无条件 |

### 奖励

- `5%` 概率直接发 `Fever`
- 否则优先发角色契合带扣
- 若已拥有契合带扣，则随机发其他高级带扣
- `Command` 系不会通过这里随机出来

## 15.7 邪魔徒刷怪

触发前提：

- 存活人类大于 1
- 存活邪魔徒少于 3

概率：

- 前 10 回合：`25%`
- 之后：`0.15 + round * 0.01`
- 若当前场地是 `Carnival`：直接 `100%`

刷怪类型：

- `Pawn`：普通步兵
- `Rook`：精英战车邪魔徒
- `Rider`：Boss 邪魔徒骑士

怪物数值会按回合数缩放：

```ts
scale = 1 + (round / 10) * 0.15
```

## 15.8 决胜阶段与邪魔徒内斗

### 决胜阶段

- 第 `50` 回合开启
- `DGP 骑士保护协议` 永久解除
- 从此人类互殴不再减伤

### 邪魔徒内斗

当场上进入：

- 只剩 1 名人类
- 但至少还有 2 个邪魔徒

就会触发“邪魔徒失控”，怪物会开始互打。

## 19. Command 系完整机制

## 19.1 `Command_Raising` 的定位

它不是普通大带扣，而是一条**成长路线**：

- 本体数值不算最离谱
- 但命中能给自己积攒 `commandCharges`
- 充能满了以后，会直接进化到 `Command_Twin`

## 19.2 充能规则

- 每次命中目标会获得充能
- 某些技能还能额外提供 `bonusCharge`
- 满足 `10` 点充能后觉醒

## 19.3 觉醒为 `Command_Twin`

当充能达到 `10` 时：

- 清空当前充能
- 强制切到 `Jet` 初始模式
- 把除 `Command_Raising` 外的其他高级带扣全部卸下
- `inventory` 清空
- `feverSlot` 清空
- 更新属性并**直接回满血**
- 角色进入神话级 `Command_Twin`

同时，被卸下的高级带扣会散落到地上，成为全场新资源。

## 19.4 `Command_Twin` 的实际效果

- 占据整个驱动器
- 无法再装备新带扣
- 每次行动有 `40%` 概率在 `Jet / Cannon` 之间切换模式
- `Jet` 偏高速多段与真实伤害踢
- `Cannon` 偏重炮、AOE、暴击与贯盾

## 19.5 不同 ID Core 对 `Command_Raising` 基础攻击的改写

引擎会按 `idCore.id` 改写跃升斩剑的基础攻击：

| ID Core | 额外改写 |
| --- | --- |
| `Fox` | 改成更高速的 3 段连斩 |
| `Bull` | 有机会变成自残蓄力，伤害更高并额外充能 |
| `Tanuki` | 有概率变成 4 段高赔率攻击并额外充能 |
| `Cat` | 带 `Dodge Up` |
| `Pumpkin` | 带护盾 |
| `Wolf` | 低血越强，并带吸血 |
| `Penguin` | 生成护盾 |
| `Eagle` | 必中精准打击 |

所以 `Command_Raising` 不是谁拿都一样，它会被 ID Core 二次塑形。

## 20. 邪魔徒与分身

## 20.1 邪魔徒列表

| 单位 | 等级 | 面板 | 技能特点 |
| --- | --- | --- | --- |
| `Pawn` 邪魔徒步兵 | normal | `1600 HP / 35 ATK` | 基础爪击 |
| `Rook` 战车邪魔徒 | elite | `4000 HP / 70 ATK` | 带眩晕重装冲撞 |
| `Rider` 邪魔徒骑士 | boss | `8000 HP / 120 ATK` | 群体扫射 + 猛毒骑士踢 |

## 20.2 分身机制

`Ninja` 可召唤 `风遁分身`：

- 继承本体 `30%` 属性
- 持续 `3` 回合
- 拥有独立行动轮次
- 与本体属于友军关系
- 可被击杀 / 可自然消失

分身会增强 Ninja 系技能，因为不少技能都带：

- `cond: hasClone`
- `condMult: 1.5`

所以忍者只要分身在场，输出会整体抬高一个档位。

## 21. 随机性与可复现性

DGP 的随机性不是乱写的，而是统一收束到 `SeededRNG`。

## 21.1 会被 seed 固定的内容

包括但不限于：

- 场地触发与具体场地类型
- 支持者空投
- 隐藏任务完成时机
- 刷怪类型
- 行动顺序中的随机扰动
- AI 决策中的概率判定
- 技能抽取
- 暴击 / 闪避 / 状态施加等战斗随机
- 实体生成 ID

## 21.2 复现规则

只要满足：

- 同样的参赛名单
- 同样的名字顺序
- 同样的 seed

就会得到同一条战斗轨迹。

## 21.3 对玩家和开发的意义

- 玩家可以分享“这把很神”的 seed
- 开发可以复盘平衡性问题
- 日后更适合补测试和做回归验证

## 22. 一些非常重要的实现细节

这些不是设定文案，而是**代码层真实行为**。

## 22.1 `Zero` 场地并不是真的“全技能锁死”

界面文案写的是“只能用基础攻击”。

但当前代码里真正做的是：

- **不递减冷却**
- **禁用 `Boost` 的技能注入**

这意味着：

- 其他 buckle 的技能如果在进入 `Zero` 前已经可用，仍然可能继续使用
- 只是它们不会在该阶段靠回合自然转好

如果以后要做“和文案完全一致”，这里需要再改引擎。

## 22.2 `Ceasefire` 的“停战”只在特定条件下生效

代码里真正把人打人伤害改成 0 的前提是：

- 当前是 `Ceasefire`
- 场上还有邪魔徒
- 决胜阶段还没到

所以它不是无条件全场休战。

## 22.3 悬赏不是循环刷新的，而是每局一次

`bountyTriggered` 只会从 `false` 变成 `true` 一次，不会回退。

## 22.4 `Command` 系不会进普通随机池

`Command_Raising` 和 `Command_Twin` 都被排除在：

- 普通补给箱池
- 支持者替代高级池
- 隐藏任务随机高级池

它们是**事件专属资源**。

## 22.5 `Boost` 是有寿命的

很多终结技在结算后都会把 `Boost` 直接烧掉：

- 可能自动换上备用槽
- 也可能武装降级
- 极限版本还会反噬自身并附加眩晕

## 22.6 护盾真的很强

护盾不仅吸收伤害，还会拦截多种负面状态。

很多时候“先打掉盾”比“硬灌伤害”更重要。

## 23. 如果你想快速理解一局 DGP

可以用下面这套思路看：

1. **名字决定底子**
2. **ID Core 决定成长方向**
3. **前期抢到大带扣就是第一波分水岭**
4. **Fever / Boost / Command 是中后期三大节奏器**
5. **场地、悬赏、支持者会反复搅局**
6. **邪魔徒不是背景板，而是决定人类何时内斗、何时被保护的重要变量**
7. **50 回合后比赛会彻底失控**

## 24. 面向开发者的阅读顺序建议

如果你之后还要改 DGP，推荐按这个顺序看代码：

1. `components/dgp/DgpGame.tsx`
   - 先理解 UI 如何建档、播日志、回放快照

2. `lib/dgp/types.ts`
   - 理解 `Player`、`BuckleDef`、`DgpLogEntry`

3. `lib/dgp/data.ts`
   - 先看所有固定资源表

4. `lib/dgp/constants.ts`
   - 看关键回合节点与概率

5. `lib/dgp/engine.ts`
   - `calculateNextRound()`
   - `handleEvents()`
   - `handleCombat()`
   - `_processPreActions()`
   - `_executeLootAction()`
   - `_executeAttackAction()`
   - `resolveSkillCombo()`
   - `handleEnvironment()`

这样最容易建立完整心智模型。

## 25. 一句话总结

DGP 的本质不是“点技能打架”，而是：

**一个由名字建模、由带扣成长、由 AI 驱动、由随机事件不断打断，并且能够用 seed 完整复现的假面骑士式生存演算系统。**
