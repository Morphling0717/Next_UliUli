# 柚子·预言家与史尔特测试矩阵

## 测试目标

本体系用于证明两条核心规则在复杂战局中始终成立：

- 只有【柚子·预言家】本人主动攻击或受到合法攻击时才进行拼点。
- 被接管的史尔特、诗怀雅、琳琅诗怀雅、幽灵鲨和归溟幽灵鲨继续按自身规则选技、索敌和攻击，绝不进入预言家拼点。

本轮只修复确定性 Bug 和不合理日志，不根据胜率调整角色数值。

## 证据层级

### 1. 策划规则与固定回归

`scripts/namearena/audit/yuzuSurtrRuleCatalog.ts` 登记 40 条可验证规则。每条规则必须关联：

- 固定随机种子的确定性用例。
- 结构化事件断言。
- 玩家可见日志断言。
- 成功、失败和边界分支证据。

历史压力测发现的失败种子必须永久纳入回归，不得只依赖之后的随机测试再次碰到。

### 2. 故障注入

审计器必须能主动抓出人工制造的错误，至少包括：

- 被接管召唤物错误参与拼点。
- 非法索敌、主人误伤和错误目标元数据。
- 黄昏重复发动、黄昏余命过早或超次数结束。
- 重复击杀分账、重复死亡和退场后幽灵行动。
- 伤害归属错误、无前因死亡和内部 ID 泄漏。
- 角色死亡并返场后，旧生命的行动继续结算。

任何故障注入没有被审计器识别，都属于测试体系本身的失败。

### 3. 覆盖驱动深审

`deep` 是当前发布门禁，不以 527,472 场全阵容穷举作为必要条件。

A/B 阵营方向保留，用于发现阵营方向相关错误。

#### 3v3–5v5 贪心组合覆盖

- 覆盖每名特殊角色作为队友、敌人、主人和第三方的合法身份。
- 覆任意两名角色围绕柚子、牢鳄和鸮的同队、敌对和跨队关系。
- 保留每个入选阵容的阵营镜像。
- 覆盖五类接管召唤物、史尔特三种生命周期及控制、挡刀、分摊、转移、反击、OB、锁血、复活和处决。
- 场景总数硬上限为 6,000；任何覆盖义务未满足时直接失败。

#### 自适应随机压力

- 每批 1,000 场，最少 12,000 场，最多 30,000 场。
- 轮换预言家三种阶段、含水/无水、史尔特三种生命周期、预言家接管和 Herobrine。
- 连续三批新增结构行为低于当前类别总数的 0.5%，且没有新增关键分支时收敛。
- 运行满四小时仍未收敛时停止发布，先报告原因。

## 自动审计

每场战斗的全部事件和日志都逐条检查，不抽样：

- 运行错误、超时和战斗状态不变量。
- 来源、目标、伤害、护盾、状态、所有权、死亡、退场和结算因果。
- 错误拼点、非法索敌、主人误伤、重复黄昏、重复死亡和幽灵行动。
- 内部 ID、损坏数值、无前因死亡和错误的播放快照。

## 语义轨迹与人工审阅

只有在数值和因果自动核对通过后，日志才进入语义去重。

- **结构行为签名**：保留技能、行动者类型、目标关系、命中结果、护盾/挡刀/分摊/转移/反击路径、状态、所有权、阶段和死亡结果。
- **展示签名**：保留日志标签、顺序和因果结构，用于发现文案与事件不一致。
- 随机数值、运行时 ID、同类单位编号和同类随机文本不会制造新行为类别。

人工必须逐行阅读：

- 每个去重后的行为样本。
- 全部罕见分支和自动报警。
- 40 条策划规则的证据。
- 所有特殊角色与预言家/史尔特的代表交互。

审阅器会保存样本清单、已审状态和审阅结论，不能只生成归档便声称人工审阅完成。

## 运行命令

```bash
# 发布级覆盖驱动深审
NAMEARENA_FOCUSED_AUDIT_RESET=1 \
  npm run test:namearena:yuzu-surtr-deep

# 生成人工审阅清单
npm run test:namearena:yuzu-surtr-review -- --root=/path/to/audit

# 读取一页去重样本
npm run test:namearena:yuzu-surtr-review -- \
  --root=/path/to/audit --sample-page=0 --page-size=20

# 阅读后标记该页
npm run test:namearena:yuzu-surtr-review -- \
  --root=/path/to/audit --mark-page=0 --page-size=20 \
  --review-note="逐行人工审阅通过"

# 可选的远程夜间穷举
npm run test:namearena:yuzu-surtr-audit -- --profile=exhaustive
```

## 验收条件

- 零运行错误、未分类超时和状态不变量错误。
- 零错误拼点、非法索敌、主人误伤、幽灵行动、无前因死亡和重复结算。
- 完整 2v2 与 3v3–5v5 覆盖义务全部完成。
- 自适应阶段在规定场数和时间内收敛。
- 全部故障注入被识别，40 条策划规则均有确定性证据。
- 所有去重后样本和罕见分支留下人工审阅记录。
- 301 场回归、248 场机制矩阵、TypeScript、ESLint 和生产构建全部通过。

压力测产物位于配置的审计目录，不接触网站数据库，也不推送或部署到服务器。
