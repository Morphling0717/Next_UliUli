# 名字大乱斗：边狱风格状态大重做方案

> 文档状态：策划审查修订稿，尚未实装。本方案同时包含新状态系统、现有非独特状态的无损迁移计划，以及已定案的 Dota 2 式普通驱散/强驱散体系。
>
> 本文的“换皮状态统一”属于无损迁移；灼烧、流血与其他新核心关键词属于明确的玩法重做。两者必须分开提交、测试和评估，不能用“无损迁移”掩盖燃烧/流血角色的实际强度变化。

## 一、设计目标

本次重做有两个目标：

1. 在不改动现有角色平衡的前提下，建立一批与《边狱巴士》风格相符的通用状态，为后续角色、技能和构筑机制使用。
2. 将现有角色身上效果相同或高度相似的非独特状态统一到底层关键词，减少重复判断、重复数值代码和换皮状态。

本方案不把已有状态简单换名，而是优先加入拥有独立玩法循环的机制：

- 施加状态后等待攻击触发。
- 积累状态后通过特定技能引爆。
- 由角色积攒并主动消耗的战斗资源。
- 可以被未来不同角色共同利用的通用状态。
- 同一套机械效果可以保留不同角色的显示名称、图标与日志文本。
- 纯粹的状态迁移不能改变伤害、胜率、行动顺序或技能选择。

《边狱巴士》的七个核心关键词为灼烧、流血、震颤、破裂、沉沦、呼吸和充能。名字大乱斗虽然已经拥有同名的灼烧与流血，但它们仍是按最大生命百分比结算的旧式持续伤害，无法支撑强度、次数、主动引爆与资源转化。因此本方案将七个核心关键词全部纳入重做，不再把灼烧与流血视为无需处理的旧状态。现有使用者的技能数值及胜率仍需以独立迁移与平衡测试保护。

本文后续提出的洞察、偏离、残影、失位、威势、衰弱等名称属于名字大乱斗原创的边狱风格关键词，不是《边狱巴士》原作的正式状态。

角色形态、锁血、复活、反击姿态、场外 OB、召唤关系、专属标记和角色资源等必须保持独立的机制不在统一替代范围内。它们可以复用通用计算工具，但不会被改名或降级成普通关键词。

## 二、通用数据结构

这批状态不应继续把强度、触发次数、持续时间和可消耗层数全部混用在 `duration`、`stacks`、`charges` 中。新系统要同时分清机械、生命周期、计算阶段、来源归属、驱散等级和表现信息。

### 1. 状态实例

建议的完整结构如下。字段可以按机械选用，但不能再用一个字段同时表示多种含义。

```ts
interface StatusInstance {
  instanceId: string
  mechanicId: string
  identityId?: string       // 需保留的专属身份，例如 WT_REPAIRING
  legacyType?: string       // 迁移期的旧 ID，只用于兼容

  potency?: number          // 机械强度
  count?: number            // 边狱式触发次数
  remainingTurns?: number   // 定时生命周期
  charges?: number          // 可消耗激活次数
  tickMode: TickMode
  expiresOn?: ExpiryPoint

  calculationStage: CalculationStage
  damageSourceMask?: DamageSourceKind[]
  barrierInteraction?: 'absorb' | 'bypass'
  statScope?: StatScope[]
  stackMode: StackMode
  polarity: 'positive' | 'negative' | 'neutral'
  dispelTier: 'normal' | 'strong_only' | 'none'

  displayName: string
  icon: string
  groupId?: string
  attribution: StatusAttribution
  contributions?: StatusContribution[]
}

interface StatusAttribution {
  effectSourceId: string     // 技能、道具或状态外壳
  applierId?: string         // 真正施加状态的战场单位
  applierName?: string       // 施加时的名称快照
  creditActorId?: string     // 伤害、治疗与触发统计归属
  creditOwnerId?: string     // 召唤物的主人，无主人时为空
}
```

`sourceId` 只能作为读取旧数据的兼容字段，不再担任“技能名称、施加者、击杀者、召唤物主人”四种职责。

### 2. 数值与生命周期

- `potency`：一次触发、一次计算或一份资源有多强。
- `count`：只用于破裂、震颤、沉沦、呼吸等真正的“强度 × 次数”机械。
- `remainingTurns`：按某种时钟减少的持续时间。
- `charges`：被命中、攻击、暴击或使用技能时消耗的可用次数。
- 一个状态可以同时拥有 `remainingTurns` 与 `charges`，例如“3 次自身行动机会内，最多触发 2 次”。
- 只有真正的边狱式双数值状态在 `potency` 或 `count` 归零时立即移除。定时增益不能因为没有 `count` 而被误删。

状态栏建议显示为：

- `破裂 8×3`：强度 8，还能触发 3 次。
- `震颤 12×2`：强度 12，还能被爆发 2 次。
- `迅捷 13% · 3次自身行动机会`：强度与持续时间不写成乘法。
- `龙威迟滞 28% · 2次全局行动`：按现有 `0.72` 速度倍率与全局时钟显示。
- `充能 14/20`：单数值资源。

### 3. 计时方式

`tickMode` 只负责“什么时候让生命周期向前走”。普通定时状态在该回调中减少 `remainingTurns`；破裂、震颤等真正的双数值状态可以按机械明文额外减少 `count`。攻击、命中或暴击触发的可消耗次数另由 `count` 或 `charges` 负责。

- `self_opportunity`：状态拥有者获得一次自身行动机会后计时。即使因眩晕、击飞、魅惑等无法真正出手，也算消耗了自身行动机会。
- `attack_action`：只在真正完成一次攻击行动后计时，不能与 `self_opportunity` 混用。
- `global_action`：每个实际的全局行动完成后计时。
- `large_round`：所有应行动单位完成一轮后计时。
- `trigger`：只在满足指定触发条件时消耗。
- `permanent`：不自然衰减，只能被指定规则替换或移除。

`expiresOn` 进一步说明该时钟在行动开始、行动完成、大回合结束还是触发后到期，避免少一回合或多一回合。

### 4. 计算作用域

`scope` 一个字段不足以表示“改什么、在哪一步改、对什么伤害生效”。每个机械或来源外壳都必须声明：

- `calculationStage`：`effective_stat`、`standard_formula`、`post_formula`、`incoming_post_mitigation` 等精确阶段。
- `statScope`：`atk`、`mag`、`wis`、`def`、`res`、`spd`、`agl` 等受影响属性。
- `damageSourceMask`：`standard`、`custom`、`manual`、`counter`、`reflect`、`transfer`、`share`、`status`、`self_cost`、`environment` 中哪些伤害类型受影响。
- `stackMode`：累加、乘算、取最高、刷新、覆盖、替换或互斥。

统一显示名称不等于统一作用域。例如两个效果都可显示为【衰弱】，但一个只作用于标准物理伤害公式，另一个可能对自定义伤害也生效，两者不能共用一个默认遮罩。

### 5. 来源、归属与多来源叠加

- `effectSourceId` 决定技能名称、图标、日志和来源特例。
- `applierId` 表示当时在战场上施加状态的单位，`applierName` 是其退场后仍可使用的快照。
- `creditActorId` 用于伤害、治疗、击杀和触发统计；`creditOwnerId` 让召唤物功绩仍按既有规则计入主人。
- 同一来源再次施加同一机械时，按该来源明示的 `stackMode` 处理，不设粗暴的全局默认。
- 不同来源不能先合成一个数字再丢掉归属。可以保留独立状态实例，或在 `contributions` 中记录每份强度、时钟、施加者与驱散等级。
- 同一机械存在多个有效来源时，状态卡与日志的当前归属显示最新施加者；后续触发伤害、治疗、击杀和统计也归属该施加者。
- “最新施加者归属”不代表丢掉旧来源：每份 `contribution` 仍独立保留强度、时钟和驱散等级。若最新一份到期或被移除，归属回退到仍在生效的次新施加者。
- 只有一个来源时显示来源名称；多来源合并显示时，详情必须列出每份贡献，并标记哪一份是当前归属。
- 同一技能同时给予多个关键词时使用相同 `groupId`，UI 默认压缩为一张来源卡片，展开后显示机械明细。
- 装备、形态等互斥身份继续使用替换规则，例如【醒剑】替换【村好剑】，不会因复用通用计算器而同时叠加。

### 6. 驱散元数据

每个状态来源都必须声明 `polarity` 与 `dispelTier`：

- `normal`：可被普通【驱散】和【强驱散】移除。
- `strong_only`：仅可被【强驱散】移除。
- `none`：不可驱散，【强驱散】也不能移除。

驱散等级属于“这个来源产生的这份状态”，不只属于机械名称。同样是【屏障】，普通技能给予的屏障可以驱散，角色形态的剧情护盾则可以不可驱散。完整驱散规则见第七章。

## 三、核心关键词状态

### 1. 灼烧与爆燃

**类型：** 负面状态、大回合结算、可由技能提前引爆。

**定位：** 持续施压与蓄热爆发，不与流血争抢“敌人攻击时受伤”的玩法。

**建议效果：**

- 使用“强度 × 次数”，第一版强度上限为 `20`，次数上限为 `6`。
- 每个大回合的状态结算阶段，仍在战场上的灼烧持有者受到 `灼烧强度 × 6` 点固定状态伤害，然后消耗 1 次灼烧。
- 再次施加时，强度与次数分别相加并截取到各自上限；溢出数值不会自动互换。
- 灼烧伤害忽略防御与魔抗，但属于外部能量伤害，默认先由屏障吸收。
- 场外 OB 期间不结算灼烧，也不消耗次数；回场后继续保留离场前的数值。
- 灼烧伤害不会再触发破裂、沉沦、反伤或其他受击状态。
- 次数归零后移除灼烧。默认属于【可驱散】负面状态，驱散不会触发最后一次伤害。

#### 爆燃

【爆燃】是操作关键词，不是持续存在的状态。

- 只有明确写有“爆燃”的技能才能提前引爆灼烧。
- 默认立即进行 1 次完整的灼烧结算，并消耗 1 次灼烧。
- 技能可以明确声明连续爆燃数；每次都需独立消耗灼烧次数，并在目标真正死亡或转阶段时停止后续结算。
- 单纯“再次施加灼烧”不再自动爆燃；施加与引爆是两种不同的技能能力。

**日志示例：**

```text
灼烧🔥 【灼烧】火焰在 玄凝 身上蔓延，造成 72 点伤害！（灼烧 12×3）
技能💥 【爆燃】积蓄的火势被提前引爆，玄凝 再受到 72 点伤害！（灼烧 12×2）
```

### 2. 流血与关联操作

**类型：** 负面状态、攻击行为触发、可由技能主动催动。

**定位：** 让目标在主动进攻时撕裂伤口，并为未来的血魔与其他流血角色提供统一接口。

**建议效果：**

- 使用“强度 × 次数”，第一版强度上限为 `20`，次数上限为 `6`。
- 当持有者已确定将执行一次有效的主动攻击行动时，在该攻击的第一段伤害前，持有者受到 `流血强度 × 6` 点固定状态伤害，然后消耗 1 次流血。
- 流血触发与攻击最终是否命中无关；只要攻击已进入执行，伤口就会在出手前裂开。
- 因眩晕、击飞、尴尬判定失败等原因没有真正进入攻击执行时，不触发也不消耗流血。
- 普通攻击、一般攻击技能与必杀都可触发；治疗、增益、召唤、纯控制、等待反击、被动反击、反射与伤害转移不触发。
- 默认每次攻击行动只触发 1 次。只有技能明确声明“流血触发次数”时，真实独立的多段攻击才可以多次触发。
- 流血伤害忽略防御与魔抗，属于体内伤口伤害，默认绕过屏障。
- 如果流血使行动者真正死亡，本次尚未执行的攻击取消；如果只是触发锁血或转阶段而仍然存活，则由该角色的阶段规则决定是否继续原行动。
- 流血伤害的伤害、击杀与统计归当前有效的最新施加者；若该份来源失效，按通用归属规则回退到次新来源。
- 流血伤害不会递归触发破裂、沉沦、反伤或其他受击状态。
- 次数归零后移除流血。默认属于【可驱散】负面状态。
- 流血不再自带治疗削弱；需要降低治疗、再生或吸血时，应额外施加独立的【枯竭】。

#### 催血

【催血】是主动触发流血的操作关键词，不是另一个持续状态。

- 对持有流血的目标立即进行 1 次流血结算，并消耗 1 次流血。
- 技能可明确写出连续催血数；每次都消耗次数，目标死亡或转阶段后立即停止。
- 催血产生的仍是流血伤害，屏障交互、归属、击杀与防止递归的规则不变。

#### 止血

【止血】是针对流血的移除或削减操作，不是持续增益。

- 技能必须明确写出是“移除全部流血”还是“降低若干强度/次数”。
- 普通【驱散】移除可驱散流血时，等价于完全止血，不会额外触发流血伤害。
- 止血只处理【流血】，不会顺带移除【枯竭】、血魔专属资源或其他伤口类角色标记。

#### 流血伤害接口

- 每次流血结算都必须生成独立的结构化伤害记录，包含触发方式、施加者、实际失去生命、过量伤害、锁血与死亡结果。
- 系统向外暴露“流血实际造成了多少生命伤害”的唯一事件，供【血宴】等未来角色专属资源订阅。
- 通用流血机械本身不创建【血宴】或【硬血】；这两者只属于血魔角色的专属体系。
- 血魔体系的完整角色方向见 [单核血魔角色开发方向](./NAMEARENA_BLOODFIEND_DIRECTION.md)。

**日志示例：**

```text
流血🩸 【流血】玄凝 强行发动攻击，伤口在出手前裂开，受到 60 点伤害！（流血 10×2）
技能🩸 【催血】血魔引动伤口，玄凝 的流血被立即触发，受到 60 点伤害！（流血 10×1）
```

### 3. 破裂

**类型：** 负面状态、受击触发、混合固定/最大生命百分比伤害。

**定位：** 集火、多段攻击和高防御目标的克制机制。

**建议效果：**

- 使用“强度 × 次数”。
- 破裂强度第一版上限为 `20`，次数上限为 `6`。带有破裂的单位受到一次有效直接攻击时，额外受到一次破裂伤害。
- 再次施加破裂时，强度与次数分别相加并截取到各自上限；溢出的强度与次数不会互相转换，除非技能文本明确拥有专属转换规则。
- 破裂强度未达上限时，每点强度造成 `6` 点固定伤害。
- 破裂强度达到 `20` 时，本次改为造成目标最大生命 `4%` 的伤害，且单次最低为 `120` 点，用于克制高血量单位。
- 达到上限后的单次伤害不得低于“上限前一点强度”的固定伤害，避免堆满后反而变弱。
- 触发后，破裂次数减少 1。
- 次数归零后移除破裂。
- 上述数值是第一版测试基准，后续可依据实战与压力测试调整强度上限、每点伤害和满层百分比，但公式结构不再改回纯固定或纯百分比。
- 破裂伤害忽略防御和魔抗，但仍受无敌、伤害转移、傀儡格挡、锁血和死亡结算规则约束。

**触发范围：**

- 普通攻击可以触发。
- 一般技能和必杀造成的直接伤害可以触发。
- 只在实际承伤者本次 `hpDamage > 0` 时触发；未命中、无敌、法术抵挡或屏障完全吸收时不触发。
- 伤害被格挡或转移后，只检查实际承伤者身上的破裂。
- 多段技能只有在定义中声明 `statusHitCount > 1` 时才可以连续触发。只用 `hits` 乘算总伤害的旧技能默认仍是 1 个伤害事件和 1 次状态触发，不得在迁移时擅自拆分基础伤害。
- 持续伤害、反伤、伤害均摊、坠落伤害、自残和环境伤害不能触发。
- 破裂造成的额外伤害不能再次触发破裂、沉沦或其他受击关键词。
- 若基础伤害已经触发锁血或转阶段，同一命中的后续破裂不能继续伤害新阶段，也不消耗次数。

**日志示例：**

```text
破裂◆ 【破裂】小汀 的斩击撕开旧伤，克蕾儿丝菲尔 额外受到 48 点固定伤害！（破裂 8×2）
```

### 4. 震颤

**类型：** 负面状态、积累资源、需要技能引爆。

**定位：** 延迟破防与集体协作，不直接复制持续伤害。

**建议效果：**

- 使用“强度 × 次数”。
- 第一版的震颤强度上限为 `20`，次数上限为 `6`。再次施加时两项分别相加并截取到各自上限，不发生溢出转换。
- 震颤本身不造成生命伤害，也不会自动眩晕。
- 只有明确带有“震颤爆发”的技能可以引爆震颤。
- 每次震颤爆发，将等于震颤强度的数值加入目标的失衡值。
- 每次爆发消耗 1 次震颤次数。
- 震颤次数在目标的 `self_opportunity` 结算后减少 1，即使本次因其他控制无法出手也会衰减；次数归零后清除。
- 失衡值达到 `40` 时触发一次【踉跄】，随后失衡值清零。
- 失衡值没有自然衰减；只会在触发【踉跄】、真正死亡或明确写出“清除失衡”的技能生效时归零。

#### 踉跄

**类型：** 震颤派生负面状态。

**建议效果：**

- 持续到目标下一次 `self_opportunity` 结算完成。
- 闪避归零。
- 无法发动反击、等待反击和受击截停。
- 受到的非持续直接伤害提高 `25%`。
- 不会跳过行动，避免成为换皮眩晕。
- 同一单位处于踉跄期间不能再次进入踉跄，新增失衡值可留到状态结束后继续使用。
- 踉跄结束时只重新开放失衡阈值检查；若保留的失衡值已达阈值，在下一次合法的震颤爆发后再次进入踉跄，不在上一次踉跄消退的同一时点自动连锁。

**日志示例：**

```text
技能🟨 【震颤爆发】目标体内的震颤被引爆，失衡值增加 12！（震颤 12×1，失衡 32/40）
事件💥 【踉跄】目标失去平衡，闪避与反击暂时失效，受到的直接伤害提高！
```

### 5. 沉沦

**类型：** 负面状态、受击触发、精神压制。

**定位：** 通过降低士气削弱目标，而不是成为魔法版破裂。

#### 士气系统

- 士气采用完整系统，不是只在中了【沉沦】后才临时生成的状态。
- 所有玩家角色与召唤物以 `100` 点士气进入战斗，可受到【沉沦】、士气恢复和士气阈值的完整影响。
- NPC 不拥有士气，也不显示士气条。这只确定它们不发生士气增减与精神崩溃，不自动等于【沉沦】免疫。
- 对无士气 NPC 的沉沦结算为：有效直接攻击触发时，造成等于沉沦强度的固定状态伤害并消耗 1 次，不产生士气、士气阈值或精神崩溃。该替代伤害忽略防御与魔抗、默认可被屏障吸收，不能递归触发破裂、沉沦或其他受击状态，并继续遵守实际承伤者、锁血、转阶段与死亡规则。
- 士气满值且没有相关状态时，可以不在角色状态栏显示。
- 沉沦第一版强度上限为 `20`，次数上限为 `6`。再次施加时两项分别相加并截取到各自上限，不发生溢出转换。
- 带有沉沦的单位受到有效直接攻击时，士气降低等于沉沦强度的数值，沉沦次数减少 1。
- “有效”沿用破裂的实际承伤规则：只有实际承伤者 `hpDamage > 0` 时触发，未命中、无敌、完全护盾吸收和伤害被转走时不会让原目标降低士气。
- 每次自身行动机会结束时，若该单位从上一次自身行动机会结束至今没有损失过士气，则恢复 `10` 点士气；只要期间曾因沉沦或未来其他技能损失士气，本次就不恢复。即使该次行动因控制无法出手，仍会进行这项检查。
- 场外 OB 期间没有自身行动机会，因此不会自然恢复士气；回到战场后继续沿用离场前的士气。
- 普通转阶段默认保留当前士气，避免无文本依据地凭空回满；角色技能可以明确写出转阶段恢复或重置士气。
- 真正死亡会清除士气。默认复活后以 `100` 点士气重新入场；若复活技能需要延续低迷或以其他数值复活，必须在技能文本中明确写出。
- 士气不会低于 0，也不会高于 100。

#### 士气阈值

- `51-100`：没有额外惩罚。
- `26-50`：普通暴击率降低 `10` 个百分点。
- `1-25`：普通暴击率降低 `10` 个百分点，`standard/custom/manual` 直接攻击在 `post_formula` 阶段的输出降低 `15%`；不影响状态、反伤、转移、均摊、自残与环境伤害。
- `0`：触发一次【精神崩溃】，随后士气恢复至 `50`，防止连续崩溃。

锁头、`AIM` 等独立的必定暴击规则优先于普通暴击率修正，沉沦不会为了降低士气而顺带取代这些独立机制。未来若有技能要禁止必暴，必须在技能文本中单独写明。

#### 精神崩溃

**类型：** 沉沦派生负面状态。

**建议效果：**

- 下一次行动只能使用普通攻击。
- 本次攻击不能暴击。
- 行动完成后移除精神崩溃。
- 如果本次行动机会因眩晕、击飞或其他无法行动效果被阻止，精神崩溃不消耗，等到真正完成一次普通攻击后才移除。
- 精神崩溃不属于无法行动，不与眩晕或尴尬重复。

**日志示例：**

```text
沉沦🌊 【沉沦】玄凝 遭受精神冲击，士气下降 9 点！（士气 23/100，沉沦 9×2）
事件🫥 【精神崩溃】玄凝 的士气降至零，下一次行动只能勉强进行普通攻击！
```

### 6. 呼吸

**类型：** 正面状态、自身资源、暴击触发。

**定位：** 提供可积累、可消耗的暴击路线，不复制锁头的必暴击。

**建议效果：**

- 使用“强度 × 次数”。
- 每点呼吸强度增加 `5%` 暴击率。
- 呼吸强度上限为 `10`，呼吸次数上限为 `6`。再次获得呼吸时两项分别相加并截取到各自上限，不发生溢出转换。
- 只有真正打出暴击时才消耗 1 次呼吸。
- 未暴击的攻击不消耗呼吸次数。
- 锁头等必暴击效果成功触发时，也会消耗 1 次呼吸。
- 呼吸本身不增加暴击伤害，避免与高倍率必杀产生过强乘算。
- 没有剩余次数时，呼吸立即移除。

**日志示例：**

```text
暴击🫁 【呼吸】刺猬人 捕捉到转瞬即逝的破绽，攻击触发暴击！（呼吸 6×2）
```

### 7. 充能

**类型：** 中性资源状态、自身资源、技能消费。

**定位：** 由技能积攒，再由强化技能消费的循环资源。

**建议效果：**

- 充能上限为 `20`。
- 充能本身不提供攻击、防御、速度或伤害加成。
- 每次 `self_opportunity` 结算后自然减少 1 点充能。
- 未来技能可以消耗充能，获得额外伤害、护盾、追加攻击、异常强化或技能形态变化。
- 充能属于 `neutral` 角色资源，`dispelTier` 为 `none`，【驱散】与【强驱散】都不会移除。
- 只有明确写出“清除充能”或“夺取充能”的技能可以干扰它。
- 消耗充能失败时，技能应使用未强化版本，而不是整次行动失败，除非技能文本另有说明。

**日志示例：**

```text
增益⚡ 【充能】角色获得 6 点充能！（当前 14/20）
技能⚡ 角色消耗 10 点充能，强化本次攻击并展开电流护盾！（剩余 4/20）
```

## 四、补充的通用关键词

核心七类状态解决了持续伤害、行为触发、积累、引爆、士气、暴击资源和技能资源，却不能覆盖名字大乱斗现有的大量命中、闪避、攻防、治疗和护盾效果。本节补充一组名字大乱斗原创的边狱风格关键词。

这些关键词的 `potency` 直接表示百分比、百分点或护盾点数，不再采用“每层固定 8%”的粗粒度设计。例如现有技能使造成的伤害降低 `22%`，就迁移为【衰弱 22】，而不是被迫四舍五入成若干层。这样才能保证重构前后数值完全一致。

以下上限均是未来设计新技能时的策划参考，不是引擎统一强制截断的硬上限。迁移旧状态时先忠实保留现有效果；若旧效果超过参考值，不得在重构阶段擅自削弱。只有士气、充能、破裂强度等机制定义本身明确包含上限，或某种状态确实存在无限叠加、行动频率失控、永久免伤等超模风险时，才为该状态单独规定玩法上限。

本章写的作用域是“新技能的推荐默认值”，不是旧状态迁移时的强制模板。旧效果必须额外登记其 `calculationStage`、`damageSourceMask`、取整位置和最低值规则，不能因为显示成同一关键词就扩大生效范围。

**新技能的默认合并规则：**

- 同方向的百分比关键词先分别相加。例如两份【威势 15】默认合计为威势 30；来源贡献仍独立保留，便于到期、驱散和归属回退。
- 互为正反的百分比关键词不直接互相减层，而是分别汇总后乘算。例如新技能的威势/衰弱、易损/防护、强攻/怯攻、迅捷/束缚、生机/枯竭默认按“先应用正向总量，再应用负向总量”结算。
- 命中率、暴击率和暴击额外伤害等以“百分点”描述的效果，默认在对应基础概率或倍率上直接加减，最后再进行 `0-100%` 等数学安全限制。
- 同一技能若需要取最高、覆盖、互斥、只消耗一份或其他特殊叠加方式，必须在技能定义和玩家可查看说明中明示，不能依赖隐藏例外。
- 以上默认只用于重做后新设计的技能。现有状态迁移继续保留原来的累加、乘算、取最高、快照与取整位置，不因采用同一显示关键词而改变平衡。

### 1. 易损

**类型：** 负面状态、承伤倍率。

- 【易损 X】使受到的非持续直接伤害提高 `X%`，默认维持 `Y` 次自身行动机会；UI 显示为“易损 X% · Y次自身行动机会”。
- 不放大持续伤害、反伤、自残、生命支付、处决和环境伤害。
- 只放大实际承伤者收到的那一份伤害，不再次放大转移或均摊产生的后续伤害。
- 未来新技能建议总有效强度不超过 `40%`。
- 与防御、魔抗下降不同，易损在常规攻防计算完成后修改最终直接伤害。

### 2. 防护

**类型：** 正面状态、承伤倍率。

- 【防护 X】使受到的非持续直接伤害降低 `X%`，默认维持 `Y` 次自身行动机会。
- 不降低自残、生命支付和明确写出“无视防护”的特殊处决。
- 防护不等于无敌。只要最终伤害大于 0，仍然视为受到攻击，并可触发合法的受击机制。
- 未来新技能建议总有效强度不超过 `40%`。

### 3. 麻痹

**类型：** 负面状态、攻击质量限制。

- 【麻痹 Y】使接下来 `Y` 次真正执行的攻击固定使用伤害随机区间最低值，且不能暴击；`Y` 存入 `charges`，不冒充状态强度。
- 普通攻击、一般攻击技能和必杀攻击都会消耗 1 次。
- 治疗、增益、召唤、纯控制和没有伤害判定的行动不消耗麻痹。
- 没有随机伤害区间的固定伤害技能仍会被禁止暴击并消耗 1 次麻痹，但“固定使用最低值”不会额外降低其数值。
- 麻痹不修改攻击力、命中率或行动速度，因此不会与衰弱、偏离或束缚重复。

### 4. 迅捷

**类型：** 正面状态、行动调度。

- 【迅捷 X】使实际行动速度提高 `X%`，默认维持 `Y` 次自身行动机会。
- 只影响行动调度，不修改闪避、技能伤害或技能冷却。
- 不同来源按各自旧公式合并；迁移阶段不能把原有乘算改成加算。
- 未来新技能建议总有效加速不超过 `50%`。

### 5. 束缚

**类型：** 负面状态、行动调度。

- 【束缚 X】使实际行动速度降低 `X%`，默认维持 `Y` 次自身行动机会。
- 不会阻止行动，不属于眩晕、尴尬、魅惑或击飞等硬性行动改变。
- 迅捷与束缚同时存在时分别汇总后乘算，不能简单互相减层。
- 未来新技能建议总有效减速不超过 `50%`。

### 6. 仇恨值

**类型：** 中性状态、目标权重。

- 【仇恨值 X】使该单位在敌方随机选取目标时增加 `X%` 的基础权重，默认维持 `Y` 次自身行动机会。
- 仇恨值只是提高概率，不是强制嘲讽。
- 宿敌、标记、剧情目标、保护对象和技能指定目标等更高优先级规则仍可覆盖随机权重。
- 无法被选中、场外 OB 或一阶段普瑞赛斯不会因为仇恨值重新变成合法目标。
- 同队单位的仇恨值应在同一次候选列表中共同换算，不能逐个重复放大总概率。

### 7. 威势与衰弱

**类型：** 输出强化与输出削弱。

- 【威势 X】使来源遮罩内的输出提高 `X%`；【衰弱 X】使其降低 `X%`。
- `statScope` 可为全部、物理或魔法，状态栏分别显示【威势】【物理威势】【魔法威势】等中文名称。
- 新技能默认只对 `standard` 与明确标记的 `custom` 直接攻击生效，不影响持续伤害、反伤、处决、生命支付、转移与均摊伤害。
- 迁移时以旧分支的实际作用域为准。例如 `WEAK`、`YUZU_ATK_DOWN`、`WT_BREECH_DAMAGED`、`RAGE` 和 `WT_RADIO_MORALE` 目前主要嵌在标准伤害公式中，不得自动扩大到所有自定义或手写伤害。
- 同时存在时先分别汇总强化和削弱，再按注册表规定的乘算顺序结算。
- 未来新技能建议单方向总有效幅度不超过 `50%`。

### 8. 强攻、怯攻、盈魔、枯魔、明识与迷惘

**类型：** 基础战斗属性强化与削弱。

- 【强攻 X】与【怯攻 X】分别使技能读取的有效攻击力提高或降低 `X%`。
- 【盈魔 X】与【枯魔 X】分别使技能读取的有效魔力提高或降低 `X%`。
- 【明识 X】与【迷惘 X】分别使技能读取的有效智力提高或降低 `X%`。
- 这些状态会影响读取对应属性的自定义伤害、治疗、护盾和召唤公式，因此不能用最终伤害类的威势或衰弱代替。
- 它们只修改战斗中的有效读取值，不永久覆盖角色基础面板，也不改写转阶段要恢复的原始属性。
- 如果现有技能直接修改了角色临时属性，迁移时必须保持原来的乘算和取整位置。

### 9. 疾行、迟行、灵巧与滞身

**类型：** 基础速度与基础敏捷强化、削弱。

- 【疾行 X】与【迟行 X】分别使技能读取的有效 `spd` 提高或降低 `X%`。
- 【灵巧 X】与【滞身 X】分别使技能读取的有效 `agl` 提高或降低 `X%`。
- 它们修改基础属性读取，可影响依赖该属性的技能公式；【迅捷】与【束缚】只修改行动调度，两类不能混用。
- 只修改攻击者命中或目标闪避公式中的局部敏捷效果，必须额外标记 `accuracy_only`、`evasion_only` 或 `accuracy_evasion_only`，不能被当成全属性灵巧。

### 10. 坚固与破防

**类型：** 双抗强化与双抗削弱。

- 【坚固 X】使有效防御和有效魔抗提高 `X%`。
- 【破防 X】使有效防御和有效魔抗降低 `X%`。
- 只改变本次伤害公式读取的有效属性，不永久修改角色基础面板。
- 不影响真实伤害、固定伤害和明确无视双抗的技能。
- 未来新技能建议强化上限 `60%`，削弱上限 `50%`。

### 11. 甲胄与裂甲

**类型：** 物理防御强化与削弱。

- 【甲胄 X】使有效物理防御提高 `X%`。
- 【裂甲 X】使有效物理防御降低 `X%`。
- 不改变魔抗，也不等同于受到伤害提高。
- 物理防御被技能归零时，归零规则优先于普通百分比修正。

### 12. 灵障与蚀障

**类型：** 魔法抗性强化与削弱。

- 【灵障 X】使有效魔抗提高 `X%`。
- 【蚀障 X】使有效魔抗降低 `X%`。
- 不改变物理防御，也不等同于法术抵挡。
- 法术抵挡负责完整挡下一次合法技能，灵障只降低通过后的伤害，两者必须继续分开。

### 13. 洞察与偏离

**类型：** 命中强化与削弱。

- 【洞察 X】使接下来 `Y` 次攻击的最终命中率提高 `X` 个百分点，`Y` 存入 `charges`。
- 【偏离 X】使接下来 `Y` 次攻击的最终命中率降低 `X` 个百分点，`Y` 存入 `charges`。
- 攻击真正进行命中判定后才消耗次数；没有攻击目标的行动不消耗。
- 普通命中率仍受全局最低与最高命中限制。
- 必中、必定落空和特殊截停的优先级高于洞察与偏离。
- 多段技能只进行一次命中判定时只消耗 1 次；每段独立命中时按实际判定次数消耗。

### 14. 残影与失位

**类型：** 闪避强化与削弱。

- 【残影 X】使有效闪避能力提高 `X%`，默认维持 `Y` 次自身行动机会。
- 【失位 X】使有效闪避能力降低 `X%`，默认维持 `Y` 次自身行动机会。
- 【失位 100】表示闪避归零，可无损承接现有的履带断裂、输入被读取等效果；【残影 100】仍表示提高闪避能力，不会因为同为 `100` 而产生相反解释。
- 它们只改变目标侧闪避，不改变攻击者命中，因此与洞察、偏离分开。
- 必中规则仍可绕过残影；无法闪避规则优先于普通残影加成。

### 15. 生机与枯竭

**类型：** 治疗强化与治疗削弱。

- 【生机 X】使受到的治疗、再生和合法吸血提高 `X%`。
- 【枯竭 X】使受到的治疗、再生和合法吸血降低 `X%`。
- 【枯竭 100】即完全禁疗，可以无损承接现有【禁疗】。
- 治疗修正后的最终治疗量最低为 `0`，不会因为枯竭超过 `100` 而倒扣生命；任何“治疗反转为伤害”的能力都必须作为独立机制明写，不能借枯竭隐式实现。
- 最大生命提升、转阶段设置生命、复活设定生命和锁血不是治疗，不受这两个状态影响。
- 同一治疗不能因“施术者治疗加成”和“受术者生机”重复读取同一个来源。
- 实装前必须先建立唯一的 `resolveHealing` 入口，把直接治疗、再生、吸血与召唤物回复都导入同一流程。目前部分治疗是调用者手动检查 `NO_HEAL`，直接迁移为【枯竭 100】会产生绕过禁疗的漏洞。
- 中心化治疗会同时修正现有绕过 `NO_HEAL` 的路径，因此应作为单独的 bug 修复提交与纯迁移分开验证。

### 16. 屏障

**类型：** 正面状态、数值护盾。

- 【屏障 X】拥有 `X` 点独立护盾值，默认最多维持 `Y` 次自身行动机会。
- 受到合法外部伤害时先扣除屏障，再扣除生命；屏障吸收量必须显示在战斗日志和蓝色护盾条上。
- 持续伤害不再使用“全部穿盾”或“全部被挡”的粗暴规则，每种来源必须声明 `barrierInteraction`。
- 【灼烧】与【水牢】的持续伤害属于外部能量或法术侵害，默认可被屏障吸收；屏障只吸收伤害，不会顺带解除对应状态或控制。
- 无士气 NPC 受到的【沉沦】替代伤害默认可被屏障吸收；屏障只吸收本次固定伤害，不会额外恢复士气或返还沉沦次数。
- 【流血】、【中毒】、【矿石病】与【破裂】属于体内或伤口内部伤害，默认绕过屏障。破裂仍只会在基础直接攻击对生命造成实际伤害后触发，因此基础攻击被屏障完全吸收时仍不触发破裂。
- 自残、主动生命支付、击飞落地、环境伤害和明确无视护盾的处决默认绕过屏障。
- 角色专属护盾或伤害来源可明示覆盖上述默认值，但必须在技能文本、来源外壳和测试中同时登记。
- 同一来源再次施加时按技能文本选择刷新、补充或覆盖；不同来源分别保留来源归属。
- 多份通用屏障同时存在时，默认按“最早到期，再按最早施加”的顺序消耗；专属护盾若有自己的优先级，必须在来源外壳中明示声明。
- 柚子目前的护盾数值由 `fighter.yuzuShield` 保存，`YUZU_BARRIER` 只是显示标记。迁移时必须一次性选定唯一真实数据源，不能让字段与状态强度同时扣减。
- 屏障吸收量、屏障破坏与由此产生的统计必须记录伤害来源和护盾来源。
- 未来普通通用屏障建议合计不超过最大生命的 `40%`。
- 柚子的【镜界护盾】可以复用屏障容器和蓝色护盾条，但仍保留镜界护盾名称及其专属来源。

### 17. 锐意与钝化

**类型：** 暴击伤害强化与削弱。

- 【锐意 X】使接下来 `Y` 次暴击的额外伤害提高 `X` 个百分点，`Y` 存入 `charges`。
- 【钝化 X】使接下来 `Y` 次受到的暴击，其额外伤害降低 `X` 个百分点，`Y` 存入 `charges`。
- 只有实际打出或承受暴击才消耗次数。
- 钝化最多将暴击削弱为普通命中伤害，不能让暴击反而低于普通伤害。
- 它们只修改暴击倍率，不修改暴击率，因此与呼吸、锁头和必中分开。

### 18. 汲取

**类型：** 正面状态、直接伤害吸血。

- 【汲取 X】使接下来 `Y` 次攻击造成的有效直接伤害按 `X%` 治疗攻击者，`Y` 存入 `charges`。
- 以敌人实际损失的生命为基数，不以面板伤害、过量伤害或被护盾吸收的伤害为基数。
- 只有一次合法直接攻击实际造成至少 `1` 点生命伤害时才消耗 1 次汲取；未命中、被无敌或法术抵挡挡下、以及伤害被屏障完全吸收时均不消耗。
- 持续伤害、反伤、状态伤害、召唤物伤害和环境伤害默认不能触发；技能可明确授予召唤物专用汲取。
- 完全禁疗时仍记录“汲取触发但治疗被阻止”，不能无日志地吞掉结果。
- 未来新技能建议普通汲取不超过 `50%`，超过此值应作为角色专属例外。

### 19. 破绽

**类型：** 负面状态、受击暴击率强化。

- 【破绽 X】使攻击该单位时的暴击率提高 `X` 个百分点，默认维持 `Y` 次目标自身行动机会。
- 【破绽 100】表示合法攻击必定暴击，可无损承接现有“受到攻击必暴击”效果。
- 破绽只影响攻击目标时的暴击判定，不提高命中率，也不改变暴击伤害倍率。
- 免疫物理暴击、不能暴击的技能、魅惑来源限制等高优先级规则仍可阻止暴击。
- 破绽按目标自身行动机会计时，不会因为短时间内被多人集火而在第一次受击后消失，除非技能明确另设“成为有效攻击目标时消耗”的 `charges`。

## 五、现有状态迁移方案

迁移的目标不是删除所有角色化名称，而是消除重复的计算逻辑。状态分为三类处理：直接统一、保留主题外壳并复用关键词、完全保持独立。

本表中的“驱散等级”是新系统的目标分类。对现有状态实装时，必须先将当前每个净化技能的真实清除名单固化为测试，再用【驱散】、【强驱散】或“指定移除”重现。例如 `WEAK` 和 `NO_HEAL` 目前不在通用负面清除名单中，不能因改名为【衰弱】或【枯竭】就突然被所有普通驱散清除。

| `GACHA_SUMMON_LIFESTEAL` 吸血牌 | 只将召唤物伤害治疗牢鳄，受召唤归属限制 | 复用汲取的实际伤害与治疗结算工具 |

以下三项也必须保留专属身份，不能误放进普通组合状态：

- `VALO_OPERATOR_PENALTY` 【冥驹笨重】会先快照原 `spd/agl`，再将速度设为 `max(80, floor(spd × 0.78))`、敏捷设为 `max(90, floor(agl × 0.68))`，到期、转点或进入残局时恢复快照。可复用【迟行】与【滞身】的计算器，但必须保留快照、最低值、取整和转点/残局身份。
- `Q_BUNNY_IDOL_AGL` 会在持有者作为攻击者时将其命中公式敏捷乘以 `1.2`，作为目标时又将其闪避公式敏捷乘以 `1.2`，因此同时影响命中和闪避，并非单纯的目标侧【残影】。迁移时保留 `accuracy_evasion_only` 身份；是否重设计为只提升闪避，属于后续平衡修改。
- `YUZU_TAUNT` 【满级嘲讽】当前会在没有更高优先级强制目标时，把合法候选池限制为带嘲讽的柚子，它是【硬嘲讽】而不是仇恨权重。它可以与通用【仇恨值】共用候选过滤工具，但必须保留强制目标身份。

上述保留身份的状态默认不从机械名称继承驱散等级，必须根据原来源单独登记。

这类状态不能被通用净化名单误判为普通增益或减益。它们继续按原规则决定能否净化、能否驱散和何时清除。

### 4. 本次完全不处理的独立机制

以下机制无论表面上是否包含攻防、减伤或控制，都不参与本次统一替代：

- 一阶段、二阶段、三阶段及角色职业形态。
- 不甘倒下、悲愿不倒、幽灵鲨锁血、归溟锁血、复活和其他致死保护。
- 反击、等待反击、受击截停、魅惑反击及全部 `CTR_*` 反击姿态。
- 场外 OB、无法选中、剧情退场与非玩家角色阶段。
- 召唤物、主人、舰长、认主、傀儡小汀、帝王之征和高级召唤物关系。
- 脊髓剑、村好剑、醒剑、插件、女人风格等装备或形态身份。
- 柚子镜界标记、鸮过江标记、战雷侦察、源石病等专属标记。
- 眩晕、冰冻、混乱、尴尬、魅惑、沉默、击飞、火力压制和水牢等行为规则不同的控制。
- 中毒和矿石病等仍保留现有独立规则、且不属于本次灼烧/流血重做范围的伤害状态。
- 无敌、控制免疫、法术抵挡、水之幻影、虚无等不同层级的防御规则。
- 锁头、必中、必定暴击和技能自带的不能暴击等高优先级命中规则。
- 再生等拥有自己结算时点的持续治疗，以及技能直接治疗。
- 天意、欧气、APM、众宾欢也、充能以外的角色专属资源和冷却标记。

“完全不处理”是指不参与效果合并：不改名称、数值、持续时间与玩法，也不把它们包装成通用关键词。它们仍需登记 `polarity` 与 `dispelTier`，但迁移时必须精确重现现有清除行为；以后若要重做，只能以对应角色或机制为单位单独设计。

## 六、机械层与表现层

### 1. 统一机械注册表

每个关键词只保留一份机械默认定义，具体来源可以明示覆盖生命周期、作用域、叠加规则与驱散等级：

```ts
MECHANICS = {
  OUTPUT_UP: {
    polarity: 'positive',
    calculationStage: 'standard_formula',
    damageSourceMask: ['standard'],
    tickMode: 'self_opportunity',
    dispelTier: 'normal'
  },
  HIT_DOWN: {
    polarity: 'negative',
    calculationStage: 'hit_check',
    tickMode: 'attack_action',
    dispelTier: 'normal'
  },
  BARRIER: {
    polarity: 'positive',
    calculationStage: 'barrier',
    tickMode: 'self_opportunity',
    dispelTier: 'normal'
  }
}
```

战斗公式通过统一查询器读取机械和来源配置，不再在伤害、命中、速度等多个文件中硬编码几十个角色状态 ID。“统一查询”不代表“统一成相同公式”，来源配置仍可保留现有阶段、遮罩、取整与最低值。

### 2. 来源外壳

角色技能负责提供表现、来源归属与必要的机械覆盖：

```ts
{
  mechanicId: 'HIT_DOWN',
  displayName: '闪光曲球',
  icon: '🔆',
  potency: 55,
  remainingTurns: 3,
  tickMode: 'self_opportunity',
  calculationStage: 'hit_check',
  polarity: 'negative',
  dispelTier: 'normal',
  attribution: {
    effectSourceId: 'valo_flash',
    applierId: user.id,
    applierName: user.name,
    creditActorId: user.id
  }
}
```

同一个【偏离】机械可以显示为【致盲】【闪光曲球】或【截停】，并保留不同精确数值。日志必须写出来源，不能只写“目标获得偏离”。

### 3. 兼容层

- 旧状态 ID 暂时通过兼容映射转换成新状态实例，避免一次性修改所有技能。
- 存档、回放或测试中出现旧 ID 时必须能正常读取。
- 旧 `sourceId` 在兼容入口按已知调用方转成 `effectSourceId`、`applierId` 或 `creditActorId`，不在新系统中继续猜测它的含义。
- 兼容层只负责转换，不能同时保留新旧两份效果，否则会造成重复增伤或重复减速。
- 所有迁移完成并经过固定种子回归后，再删除已无调用者的旧分支。

### 4. 精确数值原则

- 迁移时从当前代码读取真实倍率，不以状态描述中的“大幅”“短暂”猜测数值。
- 当前 `1.13` 加速必须迁移为精确的 `13%`，当前 `0.62` 双抗必须迁移为精确的 `38%` 削弱。
- 当前多个来源若是乘算，迁移后仍按来源逐项乘算。
- 当前只有最高值生效的状态，迁移后仍只取最高值。
- 所有四舍五入位置保持不变；提前或延后一次 `Math.floor` 都可能改变结果。
- 属性修正器、标准公式内乘数、公式后输出乘数与承伤后乘数必须分开，不能只因它们的 UI 文字相似就移动结算位置。
- 任何固定种子对局出现伤害、命中、行动顺序或技能选择变化，都说明这是平衡修改，不是无损迁移。

## 七、统一结算规则

### 1. 结构化伤害记录

每一次伤害都应生成一份 `DamageResolutionRecord`，它是战场、日志、状态触发与统计的唯一真实来源。至少记录：

- `eventId` 与 `rootEventId`：区分原始攻击、均摊份额、转移份额与后续状态伤害。
- 攻击者、原始目标、当前目标与最终实际承伤者。
- 技能来源、伤害来源类型、多段信息和归属快照。
- 公式前数值、防御后数值、护盾吸收、实际生命伤害与过量伤害。
- `missed`、`blocked`、`redirected`、`fullyShielded`、`phaseTransition`、`defeated` 等明确结果。

左侧战场数值、右侧日志和结算统计都消费同一份记录，不得各自重新推导，以免出现伤害延后、目标错位或击杀丢失。

### 2. 分阶段伤害挂钩

现有角色的格挡、转移、无敌、护盾与均摊并不在同一个时点发生，因此不设计一条强迫所有机制重排的“万能伤害顺序”。引擎改用分阶段挂钩：

1. `target_selection`：确定合法候选目标、强制目标与硬嘲讽，但此时不进行命中判定。
2. `pre_formula_replacement`：公式前替换目标，例如傀儡小汀拦截；原始目标继续保留在记录中，后续以替换后的实际目标为准。
3. `hit_resolution`：针对当前实际目标进行命中、闪避、必中与必定落空判定。若某种拦截本身明确保证“挡下”，可由该机制单独覆盖命中结果，不能悄悄沿用原目标的闪避率。
4. `base_formula`：计算攻击者属性、技能倍率、当前实际目标双抗、暴击与现有取整。
5. `pre_defense_redirect`：公式后、绝对防御前的护主与转移，例如好大儿换位、帝王之征与源石结晶承伤。
6. `absolute_defense`：无敌、法术抵挡与专属绝对防御。
7. `incoming_modifiers`：实际承伤者的易损、防护、装甲与其他作用于承伤的倍率。
8. `barrier`：柚子镜界护盾、通用屏障与其他在该位置生效的专属护盾。
9. `post_mitigation_redistribution`：防御与护盾后的伤害拆分，例如沫沫与柚子团队均摊。
10. `late_transfer`：必须在较后位置生效的伤害转移，例如屑的伤害转移。
11. `hp_and_fate`：扣除生命，处理锁血、转阶段、复活、处决与真正死亡。
12. `aftermath`：结算破裂、沉沦、汲取、受击触发、日志和统计。

纯迁移时，以当前结构化伤害轨迹为唯一基线，将每个角色挂钩注册到它现在的阶段。任何挂钩换阶段都属于玩法修改，必须单独提案、提交和测试。

### 3. 实际承伤者与均摊

- 受击状态根据实际承伤者结算，而不是最初选定目标。
- 攻击被傀儡小汀格挡时，只检查傀儡身上的破裂、沉沦、屏障和承伤状态。
- 伤害被源石结晶、帝王之征或其他机制转移时，只检查最终承受该份伤害的单位。
- 沫沫与柚子当前的团队均摊是在原伤害经防御、减伤和护盾后再分配，队友份额以 `respectDefenses: false` 结算。纯迁移不得让每份均摊再次经过队友防御或护盾。
- 一次攻击的每个子事件共享 `rootEventId`，不能重复消耗攻击者的“一次攻击”状态。
- 额外状态伤害不能递归触发其他受击状态，同一个子事件也不能重复触发同一机械。

### 4. 多段技能与状态命中次数

当前许多技能的 `hits` 只是把总伤害相乘后调用一次伤害结算。如果在迁移时直接拆成多次伤害，会改变取整、护盾、锁血、反击和转阶段。因此：

- 旧的聚合多段技能默认仍是 1 个基础伤害事件。
- 技能可额外声明 `statusHitCount`，让破裂、沉沦等状态按 N 段检查，而不拆分基础伤害。
- 已经通过循环主动调用多次伤害的技能，继续作为多个独立事件。
- 目标在某段后真正死亡或进入新阶段时，后续状态命中立即停止，不对尸体或新阶段继续结算。

### 5. 伤害来源边界

伤害不再只分“直接”和“非直接”，而是标记精确来源类型：`standard`、`custom`、`manual`、`counter`、`reflect`、`transfer`、`share`、`status`、`self_cost`、`environment`。

- 普通攻击、一般攻击技能、必杀和明确标记的协同攻击通常属于 `standard`、`custom` 或 `manual` 直接攻击。
- 灼烧、中毒、流血、破裂等属于 `status`。
- 反伤、伤害转移和队友均摊分别属于 `reflect`、`transfer` 和 `share`。
- 自爆对自身的伤害、自残和生命支付属于 `self_cost`。
- 击飞落地、矿石病、疲劳与其他战场规则属于 `environment`。
- 处决、生命设定为 1 和直接归零属于非伤害式命运处理，不进入普通伤害遮罩。

易损、防护、汲取和受击触发都读取 `damageSourceMask`，不再靠是否恰好经过某个函数来判断，以防止持续伤害与转移链无限套娃。

### 6. 场外 OB

- 丝瓜uli 和兔卷卷处于场外 OB 时不是合法目标，新状态、AOE 和攻击都无法命中她们。
- 离场期间不发生自身行动机会结算，因此自身回合的持续伤害、持续治疗与衰减暂停。
- `SYNERGY_SLACKING` 是让角色回到战场的离场计时器，必须在 OB 期间继续计时，否则角色永远无法回归。
- 纯迁移时，已有的 `global_action` 状态在 OB 期间仍按当前规则计时，不默认冻结所有全局时钟。
- 回到战场后保留离场前未到期的状态数值与来源。临时移除的舰长等关系按各自既定规则恢复，不由通用状态系统接管。

### 7. Dota 2 式驱散体系

技能效果分为三类：

- **可驱散（`normal`）：** 普通【驱散】与【强驱散】都能移除。
- **仅强驱散（`strong_only`）：** 普通【驱散】无效，只能被【强驱散】移除。
- **不可驱散（`none`）：** 普通与强驱散都不能移除。

驱散动作分为两级：

| 驱散动作 | 可驱散 | 仅强驱散 | 不可驱散 |
| --- | --- | --- | --- |
| 【驱散】 | 移除 | 不移除 | 不移除 |
| 【强驱散】 | 移除 | 移除 | 不移除 |

**方向规则：**

- 对友方使用的驱散默认只移除 `negative` 效果，也就是净化。
- 对敌方使用的驱散默认只移除 `positive` 效果。
- 要同时移除正面与负面效果，技能必须明确写出“驱散全部可驱散效果”。
- `neutral` 资源和标记默认不受驱散影响，只能被技能点名清除、偷取或消耗。
- 【强驱散】不等于“删除所有状态”，它仍然无法移除 `none`。
- 同一技能同时包含伤害与驱散时，技能定义必须明示写出 `before_damage` 或 `after_damage`；迁移旧技能时保留当前顺序，不设一个会悄悄改变结果的全局默认值。
- 现有技能若只会清除一组指定状态，且该集合无法由普通或强驱散精确表示，迁移期间就保留为“指定移除”，不得为了套用新名词而扩大清除范围。后续若将它重设计为强驱散，属于独立平衡变更。

**推荐默认分类：**

| 驱散等级 | 默认包含的机械 |
| --- | --- |
| 可驱散 | 灼烧、中毒、流血、破裂、震颤、踉跄、沉沦、易损、防护、麻痹、迅捷、束缚、威势/衰弱、基础属性强化/削弱、双抗强化/削弱、命中/闪避修正、治疗修正、通用屏障、暴击修正、汲取、破绽、沉默 |
| 仅强驱散 | 眩晕、冰冻、混乱、尴尬、魅惑、击飞、战雷击飞、火力压制、水牢、精神崩溃等强行改变行动或行为的控制 |
| 不可驱散 | 角色形态、致死保护、复活资格、场外 OB、召唤与主人关系、装备身份、仇恨值与硬嘲讽、角色专属资源、冷却标记、NPC 事件阶段、专属剧情标记 |

上表只是新机械的默认值，最终以来源外壳为准。同一机械可以因来源不同而有不同驱散等级，例如普通屏障可驱散，剧情形态生成的护盾可以不可驱散。

**特殊边界：**

- 控制免疫负责阻止状态被施加，驱散负责移除已存在状态，两者不是同一机制。
- 所有到期、驱散、强驱散、替换、死亡清除与指定移除都通过统一 `removeStatus(status, reason)` 入口，不允许调用方直接 `filter` 数组绕过退出挂钩。
- `AIRBORNE` 保持已定规则：目标下一次获得自身行动机会时，日志先显示“处于被击飞，无法行动”，然后落地并受到落地伤害。若在此之前被强驱散，则立即调用“落地”退出挂钩并结算落地伤害，不能直接删掉状态导致角色悬空或吞掉伤害。
- `INVUL`、`BKB`、`SPELL_BLOCK` 等独立防御不从名称统一继承驱散等级，每个技能来源必须单独声明。
- 组合状态按每份 `contribution` 的极性与驱散等级移除。外壳中已没有任何机械时才消失；仍有不可驱散的专属部分时不得连根删除。
- 水人的否决、处决和自身绝对净化是显式的规格外机制，不等于通用【强驱散】。
- 水人的否决可额外清除普通驱散原本不会触碰的中性效果，包括充能、仇恨值与其他角色资源。它还可按已知特例移除【不甘倒下】与【悲愿不倒】，但“规格外”不代表默认删除所有 `none` 形态和剧情标记。
- 水人的【幻影斧】是自身绝对净化，可清除自身可清理的正面、负面与点名资源，但保留【液态躯体】及角色身份。
- 上述例外只属于水人，不能被普通角色复用。
- 水人依然可按现有规则斩杀或驱散【不甘倒下】、【悲愿不倒】，但不会斩杀一阶段转二阶段的锁血。

#### 现有技能的强驱散重设计建议

下表已经过策划确认，是强驱散重设计的目标分类。实装时仍必须先保证旧清除名单无损迁移，再将下述变化作为独立玩法提交，避免在系统迁移中混入无法定位的行为变化。

| 角色与技能 | 建议分级 | 范围与边界 | 理由 |
| --- | --- | --- | --- |
| 兔卷卷【CE清除】 | 友方全体强驱散 | 清除可驱散与仅强驱散的负面效果，不动不可驱散的形态、关系和资源 | 时间轴回拨是其标志性高级支援 |

以下效果不建议升级为强驱散：

- 通用支援池中的“清除异常”、萌月沫沫十连对舰长的净化、玄凝【喝瓶取消】、刺猬人一阶段【特摄魂】，保留为普通友方驱散。
- M1 的 FPE 灭火、核生化洗消、乘员止血与模块修复，保留为“指定移除”，各自只解决文本对应的问题。
- 【欧皇护符】【悲愿不倒】【CONTINUE?】、复活、转阶段、装备替换、认主重置等清理属于致死保护、生命周期或关系修复，不冒充为主动强驱散技能；它们仍按各自明确清除名单处理。

### 8. 死亡、转阶段与复活

- 角色真正死亡时清除普通正面、负面状态、士气和失衡值。
- 一阶段转二阶段、二阶段转三阶段是否清除状态，完全沿用各角色当前转阶段规则。
- 普通转阶段默认保留当前士气；默认复活以 `100` 点士气重新入场。角色技能文本明确写出的士气重置值优先于默认规则。
- 锁血、复活和转阶段不能让同一伤害重复触发破裂、沉沦或汲取。
- 若基础伤害已触发锁血或转阶段，同一命中的后续受击状态不伤害新阶段，也不消耗本次触发资源。
- 状态伤害的日志显示 `applierName`，伤害与击杀记入 `creditActorId`；若 `creditOwnerId` 存在，则按现有召唤物规则同时归入主人。
- 施加者先于目标退场时仍保留归属快照，不能出现无来源死亡或击杀统计丢失。

### 9. NPC 与召唤物

- 普通召唤物默认可以承受破裂、震颤、沉沦和普通数值状态，并与玩家角色一样拥有 `0-100` 的完整士气。
- 召唤物的状态归召唤物自身，除非技能明确写出给主人或与主人共享。
- 召唤物造成的状态伤害、治疗和击杀通过 `creditOwnerId` 按现有规则计入主人结算，不改变战场上的实际施加者名称。
- NPC 一律没有士气，包括普瑞赛斯、最初源石、源石结晶及以后新增的舞台 NPC。沉沦对无士气 NPC 的替代结算按本章士气规则处理。
- 无法被选中的 NPC 不会因仇恨值、破裂或其他状态变成可攻击目标。

## 八、UI 与战斗日志

### 1. 状态栏

- 只有真正的强度/次数状态显示为“名称 强度×次数”；定时状态显示“效果数值 · 剩余几次自身行动机会/全局行动”；单数值资源显示当前值与上限。
- 角色来源状态默认显示角色化名称；只有多个不同来源合并时才显示通用机械名称。
- 一个技能产生多个机械关键词时，默认显示一张组合状态卡，不把角色状态栏撑满。
- 所有状态都必须可以查看效果，不限于组合状态。详情至少显示完整中文说明、精确数值、叠加方式、剩余时间、剩余触发次数、计时方式、施加来源与“可驱散/仅强驱散/不可驱散”。
- 状态详情采用统一的混合交互：桌面端悬停或键盘聚焦时弹出，手机端点击后打开紧凑的底部详情层，角色详情卡中始终保留完整列表。
- 组合状态在同一详情中展开每项底层机械；单一状态也使用相同入口，不允许玩家只能凭名称猜测效果。
- 正面、负面、中性和角色独立机制使用不同边框，不只依赖颜色或图标。
- 中文映射必须与机械注册同步，任何界面都不能显示 `HIT_DOWN`、`YUZU_EVADE_DOWN` 等内部 ID。
- 屏障统一显示在血条上方或血条内部的蓝色区段，同时在状态详情中保留来源名称。

### 2. 日志规范

每次状态变化至少要回答四件事：谁施加、状态是什么、数值多少、还剩多久。

```text
减益🔆 【闪光曲球】丝瓜uli 使 玄凝 获得偏离 55，接下来 3 次攻击命中率降低 55 个百分点！
触发🔆 【闪光曲球】玄凝 的攻击受到强光干扰，本次命中率降低 55 个百分点！（剩余 2 次）
消退🔆 【闪光曲球】玄凝 终于恢复了视野。
```

- 组合状态日志先写来源名称，再写具体机械变化。
- 同一次技能给予多个增益时允许合并成一条可读日志，但伤害、治疗和死亡不能被合并吞掉。
- 状态伤害必须写出来源角色、目标、实际伤害和剩余状态数值。
- 屏障必须写出吸收值、剩余护盾与溢出到生命的伤害。
- 净化或驱散必须写出使用的是【驱散】还是【强驱散】，并逐项记录实际移除的效果。仅强驱散或不可驱散效果抵抗时，若对玩家理解结果有必要，日志要说明未被移除的原因。
- 状态被驱散时若有退出挂钩，必须先写移除原因，再写退出后果。例如强驱散击飞后，日志仍要显示落地与落地伤害。
- 伤害、护盾、转移、死亡与后续状态日志按同一 `rootEventId` 顺序输出，不允许另一个行动穿插到同一伤害链的前因后果之间。
- 旧 ID 兼容转换不应产生额外日志，避免同一状态显示两次获得。

以下《边狱巴士》状态更适合作为未来特定角色、阵营或构筑的专属机制，不在这次通用底层中提前加入：

- 狂信。
- 注视。
- 黑炎。

- 弹药。
- 特定 E.G.O 或人格独占资源。

## 十、实施阶段

### 阶段 0：冻结基线

- 保存当前主分支、固定种子战斗结果、关键日志快照和全部角色胜率基线。
- 生成现有状态审计表，逐项记录真实倍率、计算阶段、伤害遮罩、取整位置、持续时钟、叠加规则、施加来源、统计归属与当前每个清除技能能否移除它。
- 对典型攻击保存完整 `DamageResolutionRecord` 轨迹，包括目标替换、转移、防御、护盾、均摊、锁血和死亡阶段。
- 将“数值迁移”和“角色平衡”拆成不同提交，迁移期间禁止顺手调强或调弱。

### 阶段 1：建立数据模型与注册表

- 实现 `mechanicId`、`identityId`、`potency`、`count`、`remainingTurns`、`charges`、`tickMode`、`expiresOn`、`calculationStage`、`damageSourceMask`、`statScope`、`stackMode`、`polarity`、`dispelTier`、`groupId` 与完整 `attribution`。
- 建立计时器、贡献列表、来源快照、召唤物归属和旧 `sourceId` 兼容转换。
- 先不让任何现有技能使用新关键词，验证空接入不会改变战斗。

### 阶段 2：建立统一结算基础设施

- 完成 `DamageResolutionRecord` 与分阶段伤害挂钩，但将现有角色机制放回原有阶段，不重排玩法。
- 完成 `resolveHealing`，让直接治疗、再生、吸血和召唤物治疗经过同一条可记录流程。修正旧有禁疗绕过路径时使用独立 bug 修复提交。
- 完成普通驱散、强驱散、极性方向、来源定级和退出挂钩，先用测试注入状态验证。
- 建立唯一 `removeStatus(status, reason)` 入口，迁移所有直接过滤状态数组的删除路径，确保驱散与指定移除都会执行退出后果。
- 建立通用屏障容器与消耗顺序，专属护盾仍保留原挂钩和唯一真实数据源。

### 阶段 3：实现核心七类状态

- 实现灼烧、爆燃、流血、催血、止血、破裂、震颤、踉跄、沉沦、精神崩溃、呼吸和充能。
- 先建立流血伤害的唯一结构化事件，让未来血魔角色订阅实际生命伤害，不订阅预估伤害、屏障吸收或过量伤害。
- 暂时只由测试直接注入，不立即塞给旧角色。
- 确认每种状态的来源、触发次数、多段边界、转阶段边界、死亡归属和日志完整。
- 新灼烧与新流血的底层验收通过后，再逐个角色迁移现有同名技能；每名受影响角色都要单独重跑强度、团队组合与日志测试。

### 阶段 4：实现补缺关键词

- 实现易损、防护、麻痹、迅捷、束缚和仇恨值。
- 实现威势/衰弱、强攻/怯攻、盈魔/枯魔、明识/迷惘、疾行/迟行、灵巧/滞身。
- 实现坚固/破防、甲胄/裂甲、灵障/蚀障。
- 实现洞察/偏离、残影/失位、生机/枯竭、屏障、锐意/钝化、汲取和破绽。
- 完成组合状态卡片、来源详情、驱散等级提示和中文映射。

### 阶段 5：迁移单效果状态

- 按命中、闪避、速度、输出、双抗、治疗的顺序逐类迁移。
- 每迁移一类就对比固定种子的完整结构化轨迹，不能等全部改完才寻找差异。
- 旧 ID 通过兼容层转为新机械，确认没有重复结算后删除对应硬编码分支。

### 阶段 6：迁移复合与主题状态

- 将限时强化、燃曲压轴、爱心奶瓶、变身预演等改为组合关键词。
- 保留主题名称、技能日志、图标与角色来源。
- 将战雷模块、鸮的召唤联动、瓦学妹架枪惩罚、兔卷卷局部敏捷和沫沫装备接到通用计算器，但不移除其独立身份。

### 阶段 7：迁移驱散技能

- 逐个将现有净化、异常清除、增益消除与角色专属清除映射为【驱散】、【强驱散】或“指定移除”。
- 每个技能都保留原来的目标方向、实际清除集合与日志，不使用新分类顺手扩大清除范围。
- 等无损映射完成后，再以独立策划变更决定哪些技能应升级为真正的强驱散。

### 阶段 8：清理旧代码

- 确认全仓库没有旧状态的机械判断调用者后，删除兼容别名和死分支。
- 状态常量、UI 中文表、驱散元数据、AI 判断和测试夹具统一从注册表与来源定义读取。
- 不清理仍用于存档、回放或线上旧数据的兼容入口。

### 阶段 9：全量验证

- 运行完整回归、固定种子对比、FFA、无水 FFA、团队组合和 NPC 事件压力测试。
- 人工逐条审阅代表性日志与角色状态栏。
- 迁移确认无差异后，才允许在新的角色设计中正式使用破裂、震颤等新玩法。

## 十一、测试验收标准

### 1. 关键词单元测试

1. `potency`、`count`、`remainingTurns` 与 `charges` 各自获得、刷新、叠加、消耗、到期和同时存在的情况。
2. `self_opportunity`、`attack_action`、`global_action`、`large_round`、`trigger` 与 `permanent` 时钟，特别是被眩晕或击飞时是否消耗自身行动机会。
3. 同来源、不同来源、召唤物来源与来源退场后的叠加公式、日志快照、伤害归属和击杀归属。
4. 普通驱散对可驱散/仅强驱散/不可驱散的完整矩阵，以及强驱散对三类效果的完整矩阵；明确覆盖 `WEAK`、`NO_HEAL`、充能、仇恨值和不可驱散形态。
5. 友方净化只移除负面、敌方驱散只移除正面、中性默认不移除，同机械不同来源拥有不同驱散等级，以及先驱散后伤害/先伤害后驱散的技能顺序。
6. 灼烧在大回合末结算，场外 OB 暂停，屏障吸收，以及爆燃每次消耗 1 次；重复施加灼烧不得被误当成爆燃。
7. 流血在主动攻击执行前触发，未实际出手不触发，屏障无法吸收，且普通多段默认只触发 1 次。
8. 催血、止血、普通驱散、攻击前流血致死、锁血、转阶段与多次催血中止的边界；流血不再暗含枯竭。
9. 流血伤害事件只记录实际生命伤害，不重复统计转移、均摊、过量伤害或同一根事件，并可被血宴稳定订阅。
10. 强驱散击飞会正确调用落地挂钩、输出落地日志并造成现有落地伤害。
11. 破裂在未命中、全护盾吸收、单段、聚合多段、`statusHitCount`、真实多事件、AOE、反伤、持续伤害、转移和转阶段中的触发与消耗次数。
12. 震颤爆发、失衡阈值、踉跄期间保留失衡值与踉跄结束后再次触发的时机。
13. 灼烧、流血、破裂、震颤、沉沦和呼吸的强度/次数分别叠加、各自封顶和溢出不转换。
14. 沉沦士气阈值、百分点暴击修正、锁头/`AIM` 优先级、自然恢复、转阶段保留、真正死亡清除、复活重置、OB 暂停恢复，以及精神崩溃在行动被阻止时的保留。
15. 呼吸与普通暴击、锁头、必中但未暴击技能的交互；充能的获得、自然衰减、消费不足与驱散免疫。
16. 标准、自定义、手写、反击、反伤、转移、均摊、状态、自残与环境伤害分别经过哪些威势、衰弱、易损与防护遮罩。
17. 基础 `spd/agl` 修正与行动调度、命中、闪避修正不混用；通用仇恨只改权重，柚子硬嘲讽仍限制候选池。
18. 拦截先于命中判定，命中与防御读取实际目标；同时保留原始目标，确保傀儡格挡、柚子标记与多段计数不会串位。
19. `resolveHealing` 覆盖直接治疗、再生、吸血与召唤物治疗，【枯竭 100】无法被任一入口绕过，且汲取只在直接攻击实际造成生命伤害时消耗，不从护盾吸收、过量伤害或转移记录中重复治疗。
20. 多屏障消耗顺序、护盾来源统计、柚子护盾唯一数据源，以及专属护盾在原阶段的交互。
21. OB 期间无法获得新状态、自身行动时钟与士气恢复暂停、回归计时器继续、旧有全局时钟保持现状。

### 2. 无损迁移回归

- 同一固定种子下，迁移前后的每份 `DamageResolutionRecord`、行动者、技能、目标、实际承伤者、命中、暴击、伤害、护盾、治疗、转移、死亡顺序和胜者必须一致。
- 当前存在的 13%、18%、22%、26%、30%、35%、38%、45%、50%、55%、80% 等数值必须逐项对照，不能被标准层数近似。
- 旧状态与新机械不能同时生效。
- 状态结束时机必须继续按原来的自身行动、攻击判定或其他时钟结算。
- 每个现有净化或驱散技能在迁移前后移除的状态集合必须完全一致。
- 角色 AI 若通过状态 ID 判断技能选择，迁移后必须改读机械或保留的主题身份，不能导致技能池变化。

### 3. 跨机制压力测试

- 全特殊角色 FFA 与无水 FFA。
- 2v2 至 5v5 代表性队伍组合。
- 傀儡小汀格挡、沫沫分伤、柚子锁定、鸮协同攻击和牢鳄召唤物。
- 普瑞赛斯事件、源石结晶、不可选中和 NPC 退场。
- 丝瓜uli 与兔卷卷场外 OB。
- 锁血、转阶段、复活、处决、否决和状态击杀。
- 法术抵挡、控制免疫、无敌、屏障和防护同时存在的优先级。

固定种子的结构化轨迹对比是主验收标准。完成全部迁移后再跑至少 `15000` 场无水 FFA，用于发现固定样本未覆盖的系统性偏差，不能用“总胜率看起来没变”替代精确回归。若胜率超出统计波动，先按回放定位公式、目标或行动顺序差异，不能用新平衡数值掩盖迁移错误。

### 4. 人工日志与 UI 审查

- 人工阅读完整对局，检查每个状态都有施加、触发、结算、消退的前因后果。
- 检查状态伤害、屏障吸收、治疗和死亡顺序与左侧战场同步。
- 桌面端、手机横屏和多人战场均不能出现状态文字遮挡属性或内部 ID。
- 组合状态不能占用过多栏位，展开后又必须能看见完整数值。
- 同一效果来自不同角色时，日志不能丢失施加者或误写成另一角色的技能。

## 十二、完成标准

本次状态大重做只有同时满足以下条件才算完成：

1. 新的核心状态与补缺关键词都有唯一、可测试的机械定义。
2. 所有可统一的非独特状态不再在伤害、命中、速度和 UI 文件中各自硬编码。
3. 角色化名称、图标、来源和日志全部保留。
4. 必须独立的形态、装备、标记、反击、召唤和死亡机制没有被误合并。
5. 固定种子结果证明纯迁移没有改变当前战斗。
6. 普通驱散、强驱散、不可驱散、极性方向与退出挂钩都有唯一规则和完整测试。
7. 全量压力测试没有重复结算、无来源死亡、行动顺序漂移、状态时钟错误或伤害阶段错位。
8. 状态栏不会显示内部 ID，并能看懂强度、持续时间、触发次数、来源和驱散等级，也不会因组合效果重新变得拥挤。

完成后，这套体系足以承接现有非独特的基础属性、最终输出、攻防、命中、闪避、速度、治疗、护盾、暴击和吸血状态；未来新角色也能直接组合机械关键词，不必再为每个换皮名称添加一套专属判断。

## 十三、策划决策记录

### 1. 已定案

1. 所有玩家角色采用完整的 `0-100` 士气系统。
2. NPC 不拥有士气；召唤物拥有完整士气。沉沦对无士气 NPC 触发时改为造成等同强度的固定伤害并消耗 1 次，不产生精神崩溃。
3. 踉跄期间仍可正常行动，但不能闪避或反击，且受到的非持续直接伤害提高 `25%`。
4. 破裂采用混合公式，第一版数值为：强度上限 `20`、次数上限 `6`；未满时每点造成 `6` 点固定伤害；满层造成目标最大生命 `4%` 的伤害且单次最低 `120` 点。数值可在后续平衡测试中调整。
5. 灼烧重做为 `20×6` 上限的大回合末状态伤害，每次造成 `强度×6` 固定伤害并消耗 1 次；【爆燃】是额外立即结算且同样消耗次数的操作。
6. 流血重做为 `20×6` 上限的攻击行为触发状态，每次造成 `强度×6` 固定伤害并消耗 1 次；【催血】可主动触发，【止血】只负责移除或削减流血。
7. 流血不再内置治疗削弱，禁疗与减疗继续由独立的【枯竭】承担；【血宴】与【硬血】为血魔角色专属资源，不进入通用状态池。
8. 屏障按伤害性质区分：灼烧与水牢伤害可被吸收；流血、中毒、矿石病、破裂、自我支付与环境伤害默认穿透。
6. 多来源状态的当前显示、后续伤害、击杀和统计归属最新施加者；若该来源失效，回退到次新的有效来源。
7. 水人的否决可清除充能、仇恨值和其他中性资源，并作为规格外机制移除已点名的不可驱散效果；它不会斩杀转阶段锁血，也不默认删除所有角色形态。
8. 所有状态都必须可以查看完整效果；桌面端悬停或聚焦查看，手机端点击查看，角色详情中始终保留完整列表。
9. 第七章列出的强驱散重设计名单全部通过，实装时作为无损迁移后的独立玩法改动。
10. 不设置通用状态硬上限。只有机制自身包含上限或确实可能因叠加产生超模结果的状态，才单独定义玩法上限；概率范围、非负伤害和最小行动间隔等数学保护始终保留。
11. 普通转阶段默认保留当前士气，真正死亡清除士气，默认复活以 `100` 点士气重新入场；场外 OB 期间暂停士气自然恢复。
12. 公式前拦截先于命中判定。傀儡等拦截完成后，命中、闪避、防御与受击状态读取实际目标，同时保留原始目标用于日志和专属条件。

### 2. 上限执行原则

- **机制固有上限：** 士气 `0-100`、充能 `0-20`、灼烧 `20×6`、流血 `20×6`、破裂 `20×6`、震颤 `20×6`、沉沦 `20×6`、呼吸 `10×6` 等属于玩法定义的一部分。这些上限用于阻止高频叠加失控，首版实战后可按单个状态分别调整。
- **超模风险上限：** 只有经设计审查确认可能因重复叠加造成行动频率失控、近乎永久免伤或其他明显超模结果的状态，才单独设置上限，并在状态说明中公开显示。
- **无上限状态：** 迅捷、威势、属性强化等不能仅因属于通用关键词就自动封顶；没有明确上限声明时，引擎不得静默截断。
- **数学安全保护：** 概率限制在 `0-100%`、最终伤害不变成负数、行动间隔不降为零等属于引擎有效性保护，不算角色平衡上限，也不能被技能绕过。
