## 修复内容

- 正在展示 A 时，删除、屏蔽或修改另一封信 B 不再把 A 一并撤下；当前信件本身变化仍撤下并要求重新批准。
- 撤销、拒绝、改稿或删除刚播出的信后，待播进度跟随原位置。“下一封”不会在删除末尾信件后跳回首封；重新批准仍只入队，不自动播放。
- 共享私有管理界面修复慢请求被周期刷新反复取消的问题；后台轮询不再抹掉操作冲突提示，并使用规范化图片的真实尺寸生成审阅预览。上述共享界面代码随同一个包交付；本站本轮未改外观。

网站仍保留原信箱、话题、密钥、人工审阅和只读展示接口。服务端两项修复需要部署本包，仅更新桌面应用不会改变网站的业务规则。

## 数据迁移与回退

新增迁移标记 `0.8.2-live-queue-invalidation`，在现有 SQLite 迁移事务中替换旧的信件失效触发器，并新增队列删除前维护播放位置的触发器。不新增表或字段，不回写原信、图片、话题、批准快照、排序、已读、收藏或授权范围。迁移可重复执行。

历史版本已经丢失的播放位置无法可靠推断，按“下一封”保持空白；主播可手动选择信件上屏，或结束展示后重新开始。重启、重新连接和批准不自动播放的规则保留。

正式更新继续沿用既有备份与隔离构建流程：先备份数据库、私有图片目录、环境配置和未提交资源；在副本上执行 `npm run db:migrate` 与重复迁移验证，再切换服务。保留原数据库路径和哈希盐，包括显式空字符串。回退前保留升级后收到的新信，不以升级前整库覆盖当前数据库。旧版本运行新触发器的生产回退尚未作为本轮验收。
