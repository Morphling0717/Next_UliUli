# 风铃 0.8.0 升级记录

本站固定安装 `vendor/windchime-embed-0.8.0.tgz`，两个网站使用同一文件，SHA-256：

```text
d754cb191a07107ffa81a0b50ae6322b690481f3f720f1f131844a5f5da2d3e3
```

网站继续提供原有 `/mail` 收件箱、话题管理和连接密钥。0.8.0 桌面带来六种展示排版、文字独立滚动、图片固定在下方、置顶磁贴和“下一封”热键。主题和排版可独立搭配，新增弹幕侧栏、竖向信笺、居中短笺；切换排版保留自定宽高，也可显式使用推荐尺寸。

只安装新版桌面不会更新网站接口。网站也需要升级到此包才能保存新排版与图片区占比；桌面连接旧网站时保留本地预览并提示升级，不发送旧站不支持的字段。

## 数据与升级顺序

本次不增加数据库表；新增外观字段继续保存在既有频道外观 JSON 中。缺少字段时服务端补齐默认值，历史排版值仍兼容。信件、图片、话题、已读、收藏、批准列表、排序、旧授权哈希和有效期均继续使用原数据；旧话题密钥不会扩展成站点权限。当前画面不自动恢复。

1. 保留旧代码、锁文件、环境配置和未入 Git 的资源，对 SQLite 和私有图片目录做一致备份。运行中的 WAL 数据库不要只复制主文件。
2. 在独立副本上安装固定依赖，使用原哈希盐（包括显式空字符串），连续运行两次 `npm run db:migrate`，检查完整性、原内容及授权。
3. 执行生产构建和隔离 HTTP 回归，通过后再按站点部署流程更新。保持原 `DATABASE_PATH`、图片持久目录和管理员登录配置；不要用验证数据库替换真实数据库。
4. 0.7 服务端会严格拒绝 0.8 新增的外观 JSON 字段，不能直接换回旧镜像。回退前先停止写入，对**当时的数据库和图片**做一致备份，并单独导出各频道的完整 `appearance`。在副本上验证后，以事务只将外观 JSON 投影为 0.7 支持的字段，将旧版无法识别的排版映射为 `card`；保留全部升级后新增的信件、授权、批准和队列数据，再启动旧版服务。也可以使用提前验证过、能兼容新版外观的回退镜像。**禁止用升级前旧整库覆盖当前数据库，禁止删除信件、授权或队列以完成回退。**

本轮 UliUli 使用上述“仅转换外观”的回退方案；Mia 在实际部署前也必须先在数据副本验证该转换或选用兼容镜像。独立导出的新版外观用于之后恢复 0.8，不能替代当时的数据一致备份。

完整环境变量与连接步骤见 [网站与桌面连接](WINDCHIME-LIVE.md)。
