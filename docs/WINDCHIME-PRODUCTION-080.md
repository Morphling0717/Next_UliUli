## 真实旧镜像回退验证

0.7.0 会拒绝新增外观 JSON，不能直接把旧镜像接到未经处理的新版外观上。已在隔离副本通过 HTTP 保存六种排版，导出完整新版外观，再以事务仅转换 `appearance` 和清屏所需的 `current_snapshot`、`revision`、`activation`：仅保留旧版支持的外观字段，不支持的排版映射为 `card`，当前展示清空，其余数据保持不变。

随后实际启动保留的 0.7.0 镜像，完成 **36 次 HTTP 请求、六种排版的管理与展示验证**。旧镜像可以读取转换后的外观，首次展示为空白，原批准仍保留；信件、授权及队列未被删除或换回旧副本。结果见 [真实旧镜像回退验证](evidence/windchime-0.8.0/production/rollback-compatibility-result.json)，其中明确记录该验证未接触生产数据库。

正式回退仍须先停止写入，备份**当时**的数据、私有图片并导出完整外观，再执行经过验证的转换。禁止使用升级前旧整库覆盖当前数据库；这样会丢失升级后投稿和管理操作。也可使用提前验证过、兼容新增外观的回退镜像。

## 正式切换与公网结果

代理进程身份、挂载和实际打开的文件描述符门禁通过，确认只有网站进程能够写入数据；停站后的相关打开文件描述符为 0。最终一致备份保存在私有备份目录的 `codes.final.sqlite` 和 `data-final`，随后对当前数据迁移并切换到已经通过隔离验收的 0.8.0 镜像。

正式切换保留 **34 个既有表的所有原列内容**，原环境、持久挂载和 `main` 不变，200 个原资源摘要一致。从停止旧站写入到完整本机验收完成为 **6.34 秒**；该值包含本机验收过程，不表示精确的公网网络中断时长。

公网 `https://uliuli.cn` 的 health、capabilities、`/mail`、主站和 App Hub 均返回 200，主站与 App Hub 标题正确且独立。全部未授权管理入口与展示 frame 返回 401，旧 `/mail/live` 返回 307；200 个 public 资源逐字节核对通过。
