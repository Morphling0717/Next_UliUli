UliUli 固定使用 `vendor/windchime-embed-0.8.1.tgz`，与另一站是完全相同的文件。SHA-256：


0.8.1 修复展示窗口重新连接时的迟到请求：新展示连接建立后，会提高控制状态版本。此前准备的“上屏”或“下一封”请求因版本冲突被拒绝，新窗口保持空白，直到主播发出新的手动命令。已有健康展示窗口不会被另一个窗口的连接打断。桌面预览与观众画面同时使用一致的宽高边界，窄竖向排版不会因预览容器取值不同而失真。

网站仍提供原有信箱、活动话题、连接密钥和人工批准功能。新修复需要同时更新网站共享包，仅更新桌面不能更新服务端的握手规则。

## 数据与更新

本次不新增数据库表、字段或迁移版本。保留原信、图片、话题、已读、收藏、批准、队列顺序与授权；不会扩展旧话题密钥的权限。新握手只推进该话题的控制版本，不改变批准列表和当前健康接收端的内容。

本轮仅在 `codex/windchime-desktop-v0.6.0` 准备依赖和完成本地验证，未合并主分支、未部署网站、未访问生产数据库。原有 `tsconfig.json` 工作区内容保持逐字节不变。

正式更新时继续使用本站既有备份和隔离构建流程：保留环境配置、数据库、私有图片目录及未提交资源；在数据副本上验证迁移和构建，然后再切换服务。保持原数据库路径与哈希盐，包括显式空字符串。0.8.1 沿用 0.8.0 数据格式；不要以升级前整库覆盖之后收到的新信。跨回 0.7 的外观兼容处理见[上一版迁移说明](WINDCHIME-080-UPGRADE.md)。连接操作见[网站与桌面连接](WINDCHIME-LIVE.md)。

## 本轮实际验证

日期：2026-09-20（北京时间）。环境：Windows x64、Node 20.20.2、npm 10.8.2、Next.js 16.2.12。构建和 HTTP 服务共用一次性数据库、媒体目录与合成认证配置；服务仅监听回环地址。验证使用 `.windchime-v081-validation` 构建目录，完成后已停止临时服务。

| --- | --- |
| 固定依赖 | 两站 tgz 字节、SHA-256 和 lockfile integrity 完全一致；安装后的服务端及渲染模块与共享库测试产物一致；没有升级或改动其他依赖元数据 |
| `node scripts/test-mail-migrations.cjs` | 新库、旧库、当前库各执行两次真实 CLI 迁移通过；完整性、原业务数据、话题、旧授权范围、哈希、期限及父子撤销关系保留 |
| `node node_modules/next/dist/bin/next build` | 生产构建通过，包含 TypeScript 检查与页面生成 |
